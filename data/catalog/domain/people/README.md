## Purpose

`data/catalog/domain/people/` is an existing short-segment catalog path with an unresolved placement conflict. Its current defensible role is a compatibility index for maintainers evaluating links, redirects, migration, or retirement of historical `people` references. It must remain subordinate to the prescribed [`people-dna-land`](../people-dna-land/README.md) domain segment.

This README is for repository maintainers, People/DNA/Land domain reviewers, catalog and source stewards, privacy and sensitivity reviewers, consent and policy reviewers, evidence reviewers, release reviewers, and documentation reviewers. It explains what the path may and may not mean while the conflict remains open.

A catalog record can support discovery, review, interoperability, and release preparation. It cannot manufacture source identity, person identity, relationship truth, DNA meaning, ownership truth, legal effect, consent, evidence, admissibility, review, release, correction, or public authority. This compatibility README is weaker still: it does not establish a concrete People catalog record family.

## Validation

Validation for this path has two separate layers.

### Documentation validation

This README revision should pass:

- one H1 and a logical heading hierarchy;
- valid KFM metadata, UTF-8 text, LF endings, and a final newline;
- stable legacy fragments and explicit anchors;
- balanced Markdown tables, links, fences, HTML tags, and alert blocks;
- Mermaid source parsing;
- repository-relative link resolution against the pinned base;
- secret-like text, credential, precise-location, and real-person-data screening;
- exact remote byte readback after commit; and
- a base-to-head comparison containing only this requested file.

Documentation checks establish source quality only. They do not establish domain maturity, consent enforcement, privacy safety, proof, release, or public readiness.

### Domain and release validation

The inspected [`domain-people-dna-land` workflow](../../../../.github/workflows/domain-people-dna-land.yml) is a bounded readiness detector:

- validation holds because an accepted executable People/DNA/Land suite and consent enforcement are not established;
- proof production holds because no accepted proof producer or deterministic proof command is established; and
- release dry run holds because no accepted release command or candidate-manifest contract is established.

Those holds are evidence of fail-closed behavior, not evidence that a People or DNA catalog exists. Do not weaken, bypass, relabel, or interpret them as passing domain validation.

## Review burden

Any change beyond wording and link maintenance has a high review burden because path placement can silently create authority and because People/DNA/Land joins can create material privacy, safety, legal, consent, re-identification, discrimination, stalking, fraud, or targeting risks.

| Change class | Minimum review concern |
| --- | --- |
| Documentation wording or links | Catalog, docs, and People/DNA/Land domain review |
| Segment redirect, alias, migration, or removal | Repository architecture, affected path owners, compatibility, link, CI, release, and rollback review |
| Person, household, genealogy, or identity semantics | Domain, privacy, sensitivity, evidence, policy, legal, and correction review |
| DNA or genomic semantics | Domain, consent, revocation, privacy, security, ethics, evidence, policy, legal, retention, deletion, and release review |
| Land-ownership relationship or person-parcel join | Land-record, privacy, sensitivity, identity, evidence, policy, legal, title-boundary, correction, and release review |
| Source activation or rights change | Source, rights, license, access, retention, sensitivity, and policy review |
| Public-safe derivative or route | Deidentification, aggregation, precision, re-identification, evidence, consent where applicable, release, public-interface, and rollback review |

CODEOWNERS provides a default GitHub routing signal only. It does not prove that the necessary accountable stewards or specialist reviewers have accepted a change.
