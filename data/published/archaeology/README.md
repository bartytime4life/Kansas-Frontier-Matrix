## Purpose

<a id="1-scope"></a>

### 1. Scope

`data/published/archaeology/` is a confirmed repository path with a prior public-safe Archaeology boundary. Current governance evidence does not establish it as the canonical byte lane for every published Archaeology artifact family.

Until reviewed disposition closes the placement conflict, this directory should function as:

- a README-level compatibility and discovery surface;
- a bounded inventory or disposition index that points to verified family-first lanes;
- a home for migration, correction-routing, or retirement sidecars that do not duplicate release authority; and
- a deny-by-default boundary for any legacy or externally managed references discovered later.

It is downstream of release decisions. It does not admit raw captures, approve release, define policy, prove claims, assign cultural authority, or create a public API.

## Authority level

**Existing, placement-conflicted compatibility/index lane; non-authoritative for release, policy, truth, schema, cultural review, public serving, or canonical artifact-family placement.**

Directory Rules v1.4 place published artifacts under family-first paths such as `data/published/layers/<domain>/`. The verified Archaeology layer lane is [`data/published/layers/archaeology/`](../layers/archaeology/). The requested direct domain path is therefore preserved without being silently promoted to canonical authority.

Authority remains separated:

```text
contracts/        = semantic meaning
schemas/          = machine-checkable shape
policy/           = admissibility decisions
data/proofs/      = evidence and proof support
release/          = release, correction, withdrawal, and rollback decisions
data/published/   = approved public-safe artifact bytes and delivery sidecars
governed APIs/UI  = bounded public delivery
```

## Publication gates

<a id="5-publication-gates"></a>

### 5. Publication gates

Before an Archaeology artifact becomes current public output, verify:

- release authority exists under `release/` and binds the exact artifact digest;
- every consequential claim resolves to evidence and citation support;
- validation completed with inspectable finite outcomes and safe diagnostics;
- catalog and identifier closure exists for the released artifact;
- policy permits the named audience and surface;
- required cultural, rights-holder, sovereignty, consent, sensitivity, and independent release reviews are complete;
- the public-safe transform is named, versioned, deterministic where required, and receipt-backed;
- source rights and license permit the exact use;
- public clients use a governed interface or approved released-artifact route;
- correction, stale-state, cache-invalidation, withdrawal, and rollback paths are recorded and testable; and
- integrity refs bind the carrier, support packet, and release record.

If any gate is unresolved, keep the artifact upstream or held. Do not copy it here as a workaround.
