## 1. Purpose

`data/proofs/validation_report/atmosphere/` is the Atmosphere / Air specialization of the parent [ValidationReport proof-support lane](../README.md).

Its durable job is to make future validator outcomes inspectable for Atmosphere candidates involving:

- air observations, AQI reports, PM2.5 and ozone records;
- regulatory archives and low-cost sensor products;
- model fields, forecasts, AOD, remote-sensing masks, and smoke context;
- weather observations, stations, climate normals, and anomalies;
- derived or fusion products and advisory context; and
- downstream proof, catalog, review, release, correction, withdrawal, and rollback dependencies.

A future accepted report should make it possible to determine:

1. which candidate and immutable input digest were evaluated;
2. which accepted contract, schema, validator, ruleset, fixture set, policy basis, and runtime mode applied;
3. which source roles and knowledge characters were preserved;
4. which units, time facets, freshness state, rights, sensitivity, evidence, and release-support gates ran;
5. which finite result vocabulary applied to each result family; and
6. which receipts, EvidenceBundles, ProofPacks, review records, release candidates, correction records, and rollback targets consume or constrain the result.

The report profile remains **PROPOSED** until accepted semantic and machine contracts, deterministic tooling, representative fixtures, executable tests, and review evidence establish it.

## 5. Atmosphere validation responsibilities

The following responsibilities are retained as the **proposed acceptance profile** for future Atmosphere ValidationReport tooling. They are requirements to prove, not claims of current executable enforcement.

1. **Knowledge-character validation** — preserve distinctions among observed sensors, public AQI reports, regulatory archives, low-cost sensors, model fields, remote-sensing masks, climate normals or anomalies, derived fusion, and advisory context.
2. **Conflation denial** — AQI is not concentration; AOD is not PM2.5; model fields are not observations; low-cost sensors require correction, caveats, confidence, and limitations before consequential public use.
3. **Unit and time validation** — keep units, averaging periods, issue time, expiry time, observed time, valid time, model-run time, retrieval time, release time, and correction time explicit where material.
4. **Freshness and stale-state validation** — bind cadence, freshness threshold, evaluation time, stale result, expiry behavior, and visible stale posture.
5. **Low-cost sensor validation** — check calibration or correction, trust state, confidence, limitations, station or network context, and source role.
6. **Advisory-context validation** — require official-source reference, issue and expiry times, referral posture, and denial of KFM-authored life-safety instructions.
7. **Deterministic no-network validation** — default CI and dry-run paths use reviewed local fixtures and perform no live upstream fetch, sensor traffic, or nondeterministic external call.
8. **Rights and sensitivity validation** — unresolved rights, private station or network metadata, unsafe joins, harmful precision, or access-tier ambiguity block promotion.
9. **Evidence closure** — evidence-dependent claims resolve through EvidenceRef to EvidenceBundle or return a finite non-answer or failure outcome.
10. **Release-support validation** — report results bind the applicable ProofPack, review, release, correction, withdrawal, and rollback dependencies without making those decisions.

## 6. Required validation result families

The matrix below preserves the v0.1 report families and outcomes as a **PROPOSED documentation profile**. It is not an implemented universal enum. An accepted contract must define each family's vocabulary and cross-family aggregation rules without collapsing governed-AI, policy, test, workflow, and release states.

| Result family | Required checks | Proposed finite outcomes |
|---|---|---|
| `schema_shape` | Required fields, enums, versions, JSON shape, contract pairing. | `PASS`, `WARN`, `ERROR` |
| `knowledge_character` | Correct role for sensor, AQI report, archive, low-cost sensor, model, mask, anomaly, fusion, and advisory context. | `PASS`, `DENY`, `ERROR` |
| `source_role` | Source role for this use; no role inferred from brand or convenience. | `PASS`, `WARN`, `DENY`, `ABSTAIN` |
| `unit_semantics` | µg/m³, ppb, AQI bucket, index category, model unit, raster scale, station channel, and averaging period. | `PASS`, `DENY`, `ERROR` |
| `time_semantics` | Observed, valid, issue, expiry, model-run, retrieval, release, and correction time separation. | `PASS`, `WARN`, `HOLD`, `ERROR` |
| `freshness_stale_state` | Cadence, evaluation time, freshness threshold, stale flag, and expiry behavior. | `PASS`, `WARN`, `HOLD`, `DENY` |
| `low_cost_sensor` | Correction, calibration, caveats, confidence, limitations, and network metadata. | `PASS`, `HOLD`, `DENY` |
| `model_remote_sensing` | Model-as-model, AOD-as-AOD, mask-as-mask, and no observation collapse. | `PASS`, `DENY` |
| `advisory_context` | Official source, issue and expiry, referral, and no KFM life-safety advice. | `PASS`, `DENY`, `ERROR` |
| `rights_sensitivity` | Rights, private metadata, sensitive joins, access tier, redaction, and generalization. | `PASS`, `RESTRICT`, `DENY`, `ABSTAIN` |
| `evidence_resolution` | EvidenceRef resolution, EvidenceBundle scope, citation, digest, and limitations. | `PASS`, `HOLD`, `ABSTAIN`, `DENY`, `ERROR` |
| `catalog_release_readiness` | Evidence, catalog closure, policy, review, ProofPack, candidate, correction, and rollback references. | `READY_FOR_REVIEW`, `HOLD`, `DENY`, `ERROR` |

> [!NOTE]
> `READY_FOR_REVIEW` is not `ALLOW`, release approval, publication, or a public-safety determination. A future aggregator must preserve each underlying result rather than flatten mixed vocabularies into a misleading single pass.

## 7. Validator gates

| Gate | Proof a future validator must emit | Fail-closed result |
|---|---|---|
| AQI as concentration | AQI values are not represented as µg/m³, ppb, or measured concentration. | Deny release use or require correction. |
| AOD as PM2.5 | AOD remains a remote-sensing quantity or proxy, not surface PM2.5 concentration. | Deny or require role correction and model explanation. |
| Model as observation | Forecasts, HRRR-Smoke, CAMS, fusion, and other model fields remain labeled as modeled. | Deny or require model-context labeling. |
| Low-cost sensor public use | Correction, caveats, confidence, trust state, limitations, and applicable network context are present. | Hold, restrict, or deny. |
| Advisory context | Official-source reference, issue and expiry, referral language, and no KFM life-safety instruction are present. | Deny unsafe wording or use. |
| Freshness and staleness | Cadence, retrieval time, evaluation time, expiry, threshold, and stale posture are explicit. | Hold, abstain, deny, or emit a visible stale state. |
| Unit conversion | Original and target units, averaging period, method and version, and receipt reference are bound. | Error or hold. |
| Dry-run and CI | The default validation path is deterministic and performs no live fetch. | Error or workflow failure. |
| Rights and sensitive joins | Rights, private metadata, facilities, residences, schools, hospitals, small populations, infrastructure, or other sensitive joins are policy-cleared. | Deny, aggregate, generalize, restrict, or abstain. |
| Evidence closure | Required EvidenceRefs resolve to scope-appropriate EvidenceBundles with digests and limitations. | Hold, abstain, deny, or error. |
| Release support | Required policy, review, ProofPack, candidate, correction, withdrawal, and rollback references resolve. | Hold or deny. |

- it scans `tests/domains/atmosphere/` and fails if executable test functions or classes surface before deliberate graduation;

The proof and release-dry-run jobs are also explicit holds. Their green execution would mean the hold checks ran, not that a ValidationReport was produced or that any candidate passed.

## 9. Lifecycle relationship

```mermaid
flowchart TD
  RAW["RAW<br/>source captures"] --> WQ["WORK / QUARANTINE<br/>normalize or hold"]
  WQ --> PROC["PROCESSED<br/>validated candidates"]
  PROC --> CAT["CATALOG / TRIPLET<br/>discovery and relationships"]
  CAT --> PACK["ProofPack<br/>release-support closure"]
  PACK --> REL["release/<br/>decision, correction, rollback"]
  REL --> PUB["PUBLISHED<br/>released public-safe carrier"]

  REC["receipts<br/>process memory"] -. basis .-> VR["Atmosphere ValidationReport<br/>proposed finite validator results"]
  EVD["EvidenceBundle<br/>claim evidence"] -. resolves .-> VR
  CSP["contracts, schemas, policy<br/>meaning, shape, decisions"] -. constrains .-> VR
  VR -. gates .-> WQ
  VR -. gates .-> PROC
  VR -. supports .-> CAT
  VR -. referenced by .-> PACK
  VR -. "never publishes" .-> PUB
```

ValidationReports may support several lifecycle gates, but they are accountability objects alongside the lifecycle—not a lifecycle shortcut. Promotion remains a governed state transition, and public clients use released carriers or governed interfaces rather than this internal proof path.

## 10. Review checklist

Before a future Atmosphere ValidationReport is used in proof, catalog, review, release, correction, withdrawal, or rollback work, verify:

- [ ] An accepted semantic contract and machine schema identify the report family and allowed result vocabularies.
- [ ] The report binds candidate scope, run ID, validator and ruleset versions, schema version, fixture set, input digest, and output digest.
- [ ] Results are finite, family-specific, reason-coded, and not free-text-only.
- [ ] Source role and knowledge-character distinctions are checked and preserved.
- [ ] AQI/concentration, AOD/PM2.5, model/observation, and low-cost-sensor cases are exercised with public-safe positive and negative fixtures.
- [ ] Units, averaging periods, observed time, valid time, model-run time, issue and expiry times, retrieval time, release time, and correction time are checked where material.
- [ ] Freshness evaluation time, threshold, stale outcome, and visible downstream stale posture are recorded.
- [ ] Advisory checks require an official source and deny KFM-authored life-safety instructions.

## 11. Failure modes

| Failure mode | Why it matters | Required response |
|---|---|---|
| Report stores raw source or restricted payloads | Collapses proof support into source storage and may expose protected material. | Move payload to its governed lifecycle or restricted store; retain only safe refs and digests. |
| AQI bucket passes as concentration | Publishes misleading air-quality meaning. | Deny use and correct role, label, and units. |
| AOD passes as surface PM2.5 | Remote-sensing context becomes a false concentration claim. | Deny or relabel as AOD, model, proxy, or context. |
| Model field passes as observation | Forecast or modeled output becomes observed truth. | Deny and require model-field labeling and uncertainty. |
| Low-cost sensor passes without correction or caveats | Users may overtrust non-reference-grade data. | Hold, restrict, or deny until support exists. |
| Stale context passes as current | Time-sensitive Atmosphere claims become misleading. | Emit stale posture, hold, abstain, deny, or require refresh according to policy. |
| Advisory text becomes KFM instruction | KFM is not the issuing emergency or life-safety authority. | Deny and replace with an official-source referral. |
| Live fetch occurs during default validation | CI becomes nondeterministic and may cross source or credential boundaries. | Fail the workflow and require reviewed fixtures. |
| EvidenceRef does not resolve | A fluent report can hide missing evidence. | Hold, abstain, deny, or error; never infer closure. |
| ValidationReport acts as ReviewRecord or ReleaseManifest | Collapses technical validation with human and release authority. | Keep authority in the owning object family and reference it. |
| Green explicit-hold workflow is called a pass | Readiness scaffolding is mistaken for enforcement. | Correct the claim and keep the lane held. |
| Placeholder report lands in the proof lane | Trust-shaped placement implies maturity that does not exist. | Remove through reviewed correction and use approved fixtures, templates, quarantine, or candidates. |
| Report lacks correction, withdrawal, or rollback linkage | Consequential use cannot be reversed or audited. | Hold downstream review until lineage closes. |
| Mixed result vocabularies flatten to one `PASS` | Policy, review, workflow, and release states lose meaning. | Preserve family results and use an accepted aggregation contract. |

## 12. Definition of done

- [ ] The parent [`data/proofs/validation_report/README.md`](../README.md) links an accepted ValidationReport semantic contract and schema.

- [ ] A dedicated validator checks report shape, references, result vocabularies, and public-safe disclosure.

## 17. Rollback

### Documentation rollback

Before merge, close the draft PR and abandon the scoped branch. After merge, restore prior blob `3b67083fa791b33d379b2b6fc6810c8c2f046d87` through a transparent revert commit or revert PR. Do not rewrite shared history.

No runtime, data, candidate, release, route, cache, deployment, or publication rollback is required for this README-only change because none of those states changes.

### Future operational rollback

An operational Atmosphere ValidationReport system must separately:

1. stop new producer and validator runs without deleting prior reports;
2. preserve affected report IDs, input digests, ruleset versions, and run receipts;
3. hold dependent ProofPacks, catalog closure, candidates, and releases;
4. identify every downstream consumer, cache, index, public carrier, and generated summary;
5. issue correction, withdrawal, supersession, or rollback records where governed use occurred;
6. invalidate unsafe or stale downstream projections; and
7. verify that restored behavior still fails closed on source role, evidence, rights, sensitivity, freshness, advisory, correction, and rollback gaps.

The exact operational mechanism remains `NEEDS VERIFICATION` until accepted contracts and executable tooling exist.
