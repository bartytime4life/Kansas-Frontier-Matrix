# GeneratedRuntimeProofArtifact

> `GeneratedRuntimeProofArtifact` records the lifecycle and provenance of a generated runtime-test output—such as `actual.response.json`—without treating the generated bytes as checked-in truth, evidence closure, release proof, or public authority.

## Purpose

The default KFM posture for runtime-proof actuals is hybrid:

- emit actuals during local or CI review runs;
- keep them ephemeral by default;
- retain only when a bounded review need exists;
- promote a very small canonical subset to golden fixtures only through an explicit, digest-bound test-fixture decision;
- expire, stale, invalidate, correct, supersede, or delete them through auditable records.

This contract closes the gap between generated output and governed fixture maintenance. It does not create a runtime implementation, execute a test, store payload bytes, authenticate a reviewer, or publish anything.

The generated payload itself remains in its runtime-test artifact location or CI artifact store. This record references payload bytes by digest and governed reference; it does not embed them.

## Object boundary

`GeneratedRuntimeProofArtifact` owns:

- one generated artifact identity and digest;
- artifact kind, media type, and byte size;
- runtime-proof profile and case identity;
- generator, run receipt, spec hash, and input references;
- lifecycle state, predecessor, transition time, expiry, and reason codes;
- review references;
- an explicit golden-fixture promotion decision when applicable;
- invalidation, correction, supersession, and deletion references;
- safety and non-authority declarations.

It does not own:

- the generated payload;
- an EvidenceBundle or EvidenceRef resolution;
- runtime truth;
- policy or rights decisions;
- human-review authentication;
- release, deployment, publication, or public-use permission;
- a ReleaseManifest, PromotionReceipt, ProofPack, or RollbackCard.

## Lifecycle states

| State | Meaning | Required posture |
|---|---|---|
| `EPHEMERAL` | Generated for a bounded run and expected to disappear. | Expiry required; no predecessor. |
| `RETAINED` | Temporarily kept for review or debugging. | Prior ephemeral record and expiry required. |
| `REVIEWED` | A reviewer disposition was recorded. | Non-pending review state and review references required. |
| `PROMOTED_GOLDEN` | Explicitly selected as a stable test-fixture anchor. | Approved review, digest-bound `PROMOTE_GOLDEN` decision, synthetic public-safe data, and expiry required. |
| `STALE` | No longer current because time, input, spec, or environment changed. | Prior retained/reviewed/golden state and stale reason required. |
| `INVALIDATED` | Must not be used as a review or golden anchor. | Invalidation reason plus correction or supersession linkage required. |
| `DELETED` | Payload retention ended; audit metadata remains. | Deletion receipt required; deletion does not erase lineage. |

## Allowed transitions

```text
START -> EPHEMERAL
EPHEMERAL -> RETAINED | DELETED
RETAINED -> REVIEWED | STALE | INVALIDATED | DELETED
REVIEWED -> PROMOTED_GOLDEN | STALE | INVALIDATED | DELETED
PROMOTED_GOLDEN -> STALE | INVALIDATED
STALE -> REVIEWED | INVALIDATED | DELETED
INVALIDATED -> DELETED
DELETED -> terminal
```

The validator rejects undeclared transitions. A transition record references its prior record rather than mutating history invisibly.

## Golden promotion rule

Golden promotion is test-fixture governance only. It requires:

1. `lifecycle.state = PROMOTED_GOLDEN` and `previous_state = REVIEWED`;
2. `review.state = APPROVED` with at least one `review_record_ref`;
3. `golden_promotion.decision = PROMOTE_GOLDEN`;
4. a decision ID, decision time, review refs, and artifact digest equal to `content.digest`;
5. a matching expiry in the lifecycle and decision;
6. `safety.data_class = SYNTHETIC_PUBLIC_SAFE` and all sensitive-content flags false.

A golden decision never sets KFM lifecycle `PUBLISHED`, never authorizes a runtime answer, and never replaces review, evidence, policy, release, correction, or rollback objects.

## Invariants

- Artifact and spec digests are non-placeholder SHA-256 values.
- `artifact_ref` is digest-bound to `content.digest`.
- Reference and reason-code arrays are sorted and unique.
- Generated time is not after transition time; transition time is not after expiry.
- Every non-initial state has a prior record reference.
- `INVALIDATED` records include correction or supersession support.
- `DELETED` records include a deletion receipt reference.
- Authority flags remain false and `release_ref` remains null.
- Validator output exposes only stable codes, fields, and repository-relative file names; it does not echo payload values.

## Validation

```bash
python -m unittest discover \
  --start-directory tests/validators \
  --pattern 'test_validate_generated_runtime_proof_artifact.py' \
  --verbose

python tools/validators/validate_generated_runtime_proof_artifact.py --fixtures
```

A green result proves only the proposed schema, declared local consistency, exact synthetic fixture polarity, and no-network validator behavior. It does not prove runtime correctness, reviewer identity, evidence closure, policy, release readiness, or publication.
