<a id="purpose"></a>

## Purpose

Teach the presentation boundary between a map renderer and governed KFM meaning. A style can make a layer legible; it cannot establish that the layer is true, admissible, public-safe, released, or current.

This lane is useful for small, synthetic demonstrations of:

- paint and layout choices with visible units, legends, and caveats;
- categorical and continuous color ramps with non-color labels;
- hover, selection, focus, and feature-state affordances that identify candidates rather than proof;
- explicit RELEASED, STALE, UNSIGNED, DENIED, RESTRICTED, CITATION_FAILED, and ERROR presentation states;
- reduced-motion, keyboard, contrast, text-label, and other accessibility considerations;
- the boundary between an illustrative style and an operational style manifest.

The current subtree contains this README only. It is therefore a documentation contract, not an executable or payload-bearing example.

<a id="what-belongs-here"></a>

## What belongs here

- this README and bounded documentation of the style/trust-state teaching boundary;
- synthetic paint/layout fragments or safely transformed snippets, if separately added and visibly marked;
- legend and color-ramp examples that name units, classification method, missingness, and limitations;
- trust-state examples that use text, symbols, patterns, or labels in addition to color;
- hover/selection examples that identify candidates and route readers toward the Evidence Drawer or governed API;
- accessibility notes and negative-state walkthroughs that do not claim the underlying data is cleared for exposure;
- links to the verified operational home that the example must not replace.

Every future file must identify its learning objective, real-versus-synthetic status, expected finite outcome, operational home, validation boundary, and correction trigger. If a style fragment would be copied into a runtime, it must graduate through the owning app/package and its applicable contract, policy, test, and release review; copying is not graduation.

<a id="guardrails"></a>

## Guardrails

| Risk | Guardrail |
|---|---|
| Style becomes truth | Evidence and release state remain authoritative. |
| Style becomes geoprivacy | Filters, opacity, zoom, and labels are not protection. |
| Color becomes policy | Use semantic text, symbols, patterns, and finite reason codes. |
| Feature selection becomes proof | Selection is a candidate; the Evidence Drawer and governed evidence path resolve support. |
| A screenshot becomes runtime proof | Record the exact runtime, data, style, browser, and validation boundary or abstain. |
| A copied snippet becomes a second writer | Graduate it through the owning app/package and retire the example copy or keep the boundary explicit. |
