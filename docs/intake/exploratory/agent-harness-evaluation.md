# Agent harness evaluation for Kansas Frontier Matrix

**PROPOSED.** Test whether a compact, revision-bound task packet improves
agent verification and abstention on synthetic KFM work. Start with the
existing operating contract, directory rules and evaluator harness contract.
Use this experiment to test a contribution workflow under those sources of
authority. [AI Build Operating Contract](../../doctrine/ai-build-operating-contract.md) · [Directory Rules](../../doctrine/directory-rules.md) · [Evaluator harness](../../../contracts/ai/evaluator_harness/README.md)

## Assemble context around the claim

- Give the agent one claim, affected lane, base revision, allowed paths,
  relevant authority documents, check command and acceptance criteria. Pair
  the nearest maintained README with the governing contract, schema, policy
  and fixture when the task needs them. Show related paths on demand.
- Preserve evidence lineage. Record input fixture identity, source role,
  available provenance, applicable policy and material omissions. Cite the
  source supporting the specific claim and abstain when it cannot be supported.
  Keep quarantined or restricted evidence out of public task packets and logs.
- Keep tool scope and promotion authority with the existing controls.
  Start with read-only inspection and allowlisted fixture validation. Treat
  watcher results, source payloads and agent output as observations or proposals.
  Record review, trust decisions and publication state separately.
- For multi-session work, resume from a short repository-relative record of
  the revision, current lane, evidence, checks with outcomes and unresolved
  issues. Recheck the revision, current policy and fixture identity before
  reusing old results. Keep runtime feedback tied to the exact check and input.
  [Contribution workflow](../../../CONTRIBUTING.md) · [Readiness lanes](../../readiness-lanes.md)

## First experiment

Use one eligible synthetic fixture and one matched fixture with required
provenance absent or in conflict. Keep the model, tool permissions, checkout,
time budget and scoring criteria fixed. Compare the existing onboarding route
with the same route plus a task packet that points to the controlling contract,
policy and check. Run the same verifier from the actual fixture entry point
and have a reviewer independently compare the report to the source and check
output. [Evaluator harness fixtures](../../../fixtures/contracts/v1/ai/evaluator_harness/cases.json)

| Criterion | Acceptable result |
| --- | --- |
| Eligible fixture | Supported status and citation, with the relevant check and exact input identity recorded. |
| Missing or conflicting evidence | Explicit abstention or scoped hold with the unmet condition visible. |
| Assumed authority | Zero claims of admission, owner approval or publication from a generated report or passing check. |
| Operational value | Preserve baseline passes and reduce time to a supported answer, wrong-path searches, or human interventions. Select the improvement target before running. |

Record elapsed time, tool calls, model usage where available, reviewer
corrections and unresolved checks. Keep failed attempts and check attribution
visible. Use the existing evidence and generated-receipt conventions if the
experiment proceeds. Keep publication, release and lifecycle changes subject to
their own evidence and review. [Existing exploratory source map](pass9-ai-evaluator-harness-source-map.md)

## Reference patterns

- Stage a small trial with session continuity and a separate verifier. [Learn Harness Engineering](https://github.com/walkinglabs/learn-harness-engineering)
- Own state, typed outcomes and the transition logic around model calls. [12-Factor Agents](https://github.com/humanlayer/12-factor-agents)
- Point to the nearest maintained guidance and exact local checks. [AGENTS.md](https://agents.md/)
- Define an observable claim, admissibility and abstention criteria before edits. [GitHub Spec Kit](https://github.com/github/spec-kit)
- Study persistent state and human gates without introducing another authority path. [Deep Agents](https://github.com/langchain-ai/deepagents)
- Use a short trace of task, bounded action, observation and check. [Mini SWE Agent](https://github.com/SWE-agent/mini-swe-agent)
- Compare context and permission designs, verifying influential claims against upstream. [Awesome AI Anatomy](https://github.com/NeuZhou/awesome-ai-anatomy)
- Reuse the existing evaluator first and consider isolated benchmark packaging when workload warrants it. [Harbor](https://github.com/harbor-framework/harbor)
