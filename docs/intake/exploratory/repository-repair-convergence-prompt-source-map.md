## Retained bounded lessons

### 1. Coordination state is not KFM authority

A repair campaign may record ownership, scope, phase, validation, branch, pull request, and next action. Those facts coordinate engineering work only. They cannot become a `SourceDescriptor`, `EvidenceBundle`, `PolicyDecision`, `PromotionDecision`, `ReleaseManifest`, proof, review approval, or publication decision.

**Retained rule:** if a future repair backend is proposed, it must state its non-effects and owning responsibility root before it stores live claims. Absence of such a backend must not be papered over by inventing a root, registry, receipt, or authority-bearing cursor.

### 2. Recovery begins with equivalence and exact-state proof

An interrupted batch should resume only when the observed base, branch, scope, owned paths, target preimages, diff, claim, and intended acceptance boundary still match. Otherwise the safe result is reconciliation, rollback through an already approved path, or a new bounded batch.

**Retained rule:** a matching topic, issue, filename, or chat summary is not sufficient resume evidence. Preserve unrelated work and do not start a second writer over unresolved overlap.

### 3. Completion statements must remain scoped

One successful repair, scan, commit, or pull request proves only its named checks at its pinned state. It does not prove the whole repository is correct, converged, deployed, released, or published.

**Preferred bounded statement:** “No additional confirmed actionable defects were found within the verified scope at the pinned repository snapshot.”
