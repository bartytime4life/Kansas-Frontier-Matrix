## Unsafe direct transfers

| Packet pattern | Why direct transfer is unsafe | Required correction |
|---|---|---|
| Ready-to-copy soil schemas, validators, routes, tests, workflows, and paths | They can duplicate Pass 23/current lanes and misstate unverified implementation as accepted. | Re-derive the smallest missing contract or fixture from current owners and Directory Rules. |
| Universal quality conversion or threshold | Native vocabularies, units, depth support, uncertainty, calibration, and source roles differ. | Preserve the native code and vocabulary version; make mapping and thresholds declared, versioned decisions. |
| Station offline treated as environmental no-data, invalid reading, or environmental condition | Operational health and observation validity are different claim families. | Emit separate health and observation states and a reasoned finite outcome. |
| Generated `actual.response.json` committed or promoted automatically | A run output can be stale, environment-specific, sensitive, nondeterministic, or based on unaccepted behavior. | Default to ephemeral output; retain or promote only through an explicit reviewed record with provenance and expiry. |
| Source `ETag`, timestamp, URL, or sample response treated as interface or content identity | Transport metadata can be weak, scoped, absent, or mutable. | Preserve observations separately and compute accepted identities over declared evidence. |
| Consent, genealogy, DNA, people, or place examples copied into fixtures | Examples can expose living people, sensitive relationships, or joinable identities. | Use synthetic, non-joinable fixtures and accepted purpose/sensitivity policy. |
| Cesium implementation | It conflicts with current renderer authority. | Keep only renderer-neutral time and evidence semantics. |
| Generic contract wave treated as implementation authority | Names and shapes can conflict with accepted contracts, schemas, and finite outcomes. | Reconcile against current authorities and add only a dependency-closed gap. |

## Dependency-ordered continuation

### Wave 1 - meaning and authority decisions

1. Define allowed outcome projections, degradations, and prohibited collapses across policy, release, runtime, API, UI, and export.
2. Define verifier profile identity, supported capabilities, trust/dependency inputs, and unsupported behavior.
3. Define source-native quality vocabulary identity, mapping lineage, semantic loss, unmapped state, and health-versus-observation validity.
4. Define generated runtime-proof states, retention, review, golden promotion, expiry, invalidation, correction, and deletion.
5. Define observed-interface identity, compatibility window, deprecation, dual-read, migration decision, rollback, and retirement.

### Wave 2 - bounded offline proofs

After the applicable Wave 1 decision closes, admit at most one no-network proof:

- a synthetic parity report that detects finite-outcome collapse;
- a synthetic verifier matrix with supported and unsupported profiles;
- a synthetic native-quality mapping with unknown code, semantic loss, offline station, invalid reading, and missing support;
- a synthetic generated proof moving through ephemeral, retained, promoted, stale, and invalidated states; or
- a synthetic interface migration with old/new contract observations and a rollback hold.

### Wave 3 - lane adoption

Live soil, HLS, STAC, Wikidata, genealogy, DNA, source APIs, consent stores, renderer code, routes, packages, CI workflows, and releases remain later work. Each requires accepted source, rights, sensitivity, owner, contract, schema, policy, tests, failure behavior, correction/rollback, and separate exact authorization.

### Recommended next bounded action

**PROPOSED:** define a contract-only generated runtime-proof artifact record with synthetic `ephemeral`, `retained_for_review`, `promoted_golden`, `stale`, `invalidated`, and `deleted` fixtures. Bind runner, contract, fixture, configuration, dependency, environment, and digest identity; do not treat a passing output or promoted golden as official truth.
