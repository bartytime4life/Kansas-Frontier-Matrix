## Retained bounded lessons

### 1. Acceptance evidence must stay distributed by responsibility

The source's acceptance matrix remains useful as a review lens, but not as one monolithic gate. Evidence closure, public-store denial, policy, citations, release, rollback, freshness, sensitive geometry, AI, accessibility, attestation, and range integrity belong to their owning contracts, policies, validators, tests, workflows, and release objects.

**Retained rule:** a connected end-to-end claim is supportable only when each responsibility-specific check succeeds on the same pinned release candidate. A broad architecture document or green subset cannot substitute for that closure.

### 2. Carrier trust metadata must travel with outward artifacts

Exports and stories remain carriers. The current carrier assessment already requires evidence, policy, release, correction, rollback, and negative-state references. Future carrier-specific schemas may extend presentation fields, but they must compose that shared boundary rather than create a new truth or release family.

### 3. Similar names do not prove duplicate responsibility

The source treated `PROV.md` and `PROVENANCE.md` as a naming collision. Current main gives them explicit, complementary responsibilities: semantic claim provenance and supply-chain/build provenance.

**Retained rule:** reconcile meaning, consumers, inputs, outputs, and authority before consolidating files. Filename similarity alone is not evidence of duplication.
