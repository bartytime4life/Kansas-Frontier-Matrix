## Unsafe direct transfers

| Packet pattern | Why direct transfer is unsafe | Required correction |
|---|---|---|
| “Drop-in” watcher, policy, workflow, package, or browser code | Suggested paths and dependencies may duplicate accepted homes or bypass lane authority. | Re-derive from Directory Rules, current contracts, accepted dependencies, and an exact implementation authorization. |
| Hashing a sample or selected fields as an upstream specification | Sampling can miss material schema, semantic, link, or capability drift. | Declare a purpose-specific observation profile and preserve the complete fetched evidence needed to reproduce it. |
| Placeholder digests, identities, review states, or public labels | Example values can look like real verification or publication evidence. | Use visibly synthetic fixtures and never describe them as observed, reviewed, released, or public. |
| Signature, Rekor, SBOM, or bundle success treated as truth or release | Integrity and provenance do not prove claim support, rights, policy, review, or publication approval. | Keep verification, evidence, policy, review, release, correction, and rollback independent. |
| Browser verifier stub or library availability treated as equivalent verification | Unsupported algorithms, trust roots, canonicalization, network state, and dependency versions can change results. | Pin a verifier profile and fail safely on unsupported capability. |
| Source conflict resolved by averaging or source count | Individually admissible sources can differ in role, support, time, precision, uncertainty, and authority. | Preserve sources, declare a comparison profile, report influence, and abstain when reconciliation is not justified. |
| Historical state reconstructed from current rows only | Corrections and revocations can rewrite the answer to “what was known or trusted then.” | Preserve effective and recorded times plus append-only state transitions. |
| Cesium or peer-renderer hook | Current KFM renderer authority remains MapLibre-only unless an accepted ADR changes it. | Keep renderer-neutral semantics; do not add a peer renderer. |

## Dependency-ordered continuation

### Wave 1 - meaning and authority decisions

1. Define verification-state identity, effective time, recorded time, correction, revocation, and `as_of` query semantics.
2. Define source-conflict classes, comparison applicability, tolerance-profile identity, and influence accounting.
3. Define allowed outcome projections and degradations across policy, release, runtime, API, UI, and export surfaces.
4. Define verifier profile identity, supported capabilities, dependency/trust inputs, and fail-safe unsupported behavior.
5. Define observed-interface identity, compatibility window, deprecation, migration decision, and retirement evidence.

### Wave 2 - bounded offline proofs

After the applicable Wave 1 decision closes, admit at most one no-network proof:

- a synthetic verification timeline queried before and after correction and revocation;
- a synthetic two-source conflict with consistent, divergent, conflicting, insufficient, and revoked-source states;
- a synthetic parity report that catches answer-to-allow, abstain-to-empty, or error-to-success collapse;
- a synthetic verifier matrix with supported, unsupported, stale-trust, and dependency-mismatch outcomes; or
- a synthetic interface migration with old/new observations, a dual-read window, rollback, and retirement hold.

### Wave 3 - lane adoption

Live source probes, policy bundles, signing services, transparency logs, browser verifiers, packages, CI gates, migrations, and releases remain later work. Each requires an accepted owner, current authority, deterministic fixtures, negative cases, correction/rollback behavior, and separate exact authorization.

### Recommended next bounded action

**PROPOSED:** define a contract-only bitemporal verification-state record and synthetic replay fixtures for active, superseded, corrected, revoked, late-recorded, and unknown states. This tests the core meaning without live sources, keys, policies, or releases.
