## Directory Rules and authority basis

The accepted [Directory Rules v2](../../doctrine/directory-rules.md), adopted through [ADR-0029](../../adr/ADR-0029-adopt-directory-governance-standard-v2.md), place artifacts by responsibility root, lifecycle, authority, and exposure rather than by a packet's suggested tree.

| Packet material | Correct responsibility if later promoted |
|---|---|
| Exploratory source identity, clustering, and disposition | `docs/intake/` |
| Atlas candidate synthesis | Existing atlas register edited in place; do not create another parallel atlas carrier |
| Human-readable object meaning | `contracts/` |
| Machine-checkable shape | `schemas/` |
| Allow, deny, restrict, abstain, or obligation behavior | `policy/` |
| Executable validators and comparison tools | `tools/` |
| Domain ingestion and transforms | `pipelines/`, `pipeline_specs/`, and admitted connector/source lanes |
| Source identity, authority, rights, cadence, and access | source documentation plus `data/registry/` |
| Process memory and proof | separate governed receipt and proof roots |
| Publication, correction, withdrawal, and rollback | `release/` and governed lifecycle companions |
| Public or semi-public interaction | governed API and accepted application/package boundaries |

Packet paths such as generic `/intake`, `/output`, `schemas/fauna.yaml`, `policy/fauna_soils.rego`, and `data/catalog/<format>/...` are not carried forward as current KFM locations. Existing responsibility roots and accepted placement decisions control any implementation.

## Unsafe direct transfers

| Packet pattern | Why direct transfer is unsafe | Required correction |
|---|---|---|
| “Ready-to-commit” schema or code | The repository already has stronger or conflicting homes, object names, and validators. | Re-derive from current contracts and Directory Rules; implement one dependency-closed gap. |
| JSON Schema `nullable: true` under Draft 2020-12 | `nullable` is not the Draft 2020-12 nullability mechanism. | Use an accepted schema style such as `type: ["string", "null"]` and existing domain vocabulary. |
| Generic `data/registry -> data/work -> validators -> policy -> diff -> receipts -> publish` shortcut | It omits explicit processed, catalog/triplet, review, release, correction, and rollback authority and can imply that a watcher publishes. | Preserve the full lifecycle and watcher-as-non-publisher rule. |
| Hashing an entire record without a declared profile | Volatile timestamps, pre-existing digests, signatures, and self-referential hash fields can make identity unstable or recursive. | Pin algorithm, canonicalization version, included/excluded fields, numeric/geometry normalization, and test vectors. |
| Random jitter as sensitive-location redaction | Randomness can be non-replayable, leak through repeated releases, or mislead users about precision. | Prefer deterministic policy-approved generalization with a RedactionReceipt and effective-precision disclosure. |
| Real species, coordinates, DNA fields, kit IDs, or person examples in fixtures | Examples can expose sensitive facts or normalize unsafe test practice. | Use explicitly synthetic records with no real-world joinability. |
| Consent token as publication permission | Consent does not prove identity, evidence, rights, sensitivity, review, or release. | Compose consent as one independent gate and check current revocation before every consequential operation. |
| Cesium/CZML code as a renderer decision | A code sample cannot override renderer architecture or dependency admission. | Retain renderer-neutral temporal semantics; route any peer-renderer choice through an ADR. |
| `pmtiles verify` + signature = publish | Structural validity and signer authentication do not prove semantic truth, source rights, evidence closure, or release approval. | Keep integrity, provenance, policy, review, and release decisions separate. |
| A proximity join = historical relationship | Distance is a candidate relation, not proof of route use, causality, service, or contemporaneity. | Emit a qualified proximity candidate with time overlap, uncertainty, source roles, and query receipt. |
