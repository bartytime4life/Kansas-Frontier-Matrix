## Retained corrections and lessons

### 1. A sorted-key JSON helper is not the repository JCS authority

The source labels a `json.dumps(..., sort_keys=True, separators=(",", ":"))` helper as RFC 8785 canonicalization. Current repository evidence distinguishes that approximation from the JCS profile, especially where number serialization matters.

**Retained rule:** use the owning, versioned canonicalizer and test vectors. Do not grant an illustrative helper identity or promotion authority merely because it is deterministic for a subset of JSON.

### 2. Watcher metadata is a signal, not evidence closure

ETag, Last-Modified, status, and download-key changes can justify a review candidate. They cannot prove that a domain fact changed, that rights remain valid, or that a source may enter RAW.

**Retained rule:** watchers remain candidate-signal producers. Admission, source role, rights/currentness, sensitivity, evidence, policy, review, release, correction, and rollback keep separate owners.

### 3. Browser integrity and browser trust are different gates

The current mobile PMTiles fixture can recompute synthetic archive, sidecar, Merkle, range, and tile digests without claiming cryptographic trust. Adding a browser Sigstore verifier would introduce trust roots, dependency supply chain, certificate identity, issuer, transparency, offline material, advisory, and operational network responsibilities.

**Retained rule:** do not collapse digest integrity, signature verification, release authorization, and renderer registration into one client helper. Each result must remain finite, inspectable, policy-aware, and fail-closed.
