## Directory Rules basis

Accepted [`ADR-0029`](../../adr/ADR-0029-adopt-directory-governance-standard-v2.md) adopts [`docs/doctrine/directory-rules.md`](../../doctrine/directory-rules.md). The applicable placement reading is:

1. **A path is an authority claim.** Topic words such as `policy` and `sensitivity` do not override responsibility.
2. **`docs/` owns human explanation only.** It does not own executable policy, contracts, schemas, fixtures, decisions, protected data, release records, or runtime behavior.
3. **`policy/` owns normative admissibility source.** The current sensitivity rule-source boundary is `policy/sensitivity/`.
4. **`contracts/` define meaning; `schemas/` define machine shape.** Neither belongs in this docs lane.
5. **`tests/` own executable conformance; `fixtures/` own reusable synthetic inputs.**
6. **Domain guidance stays with the domain.** Fauna identity, occurrence, and evidence distinctions belong under the fauna documentation responsibility.
7. **Security and exposure guidance stays with its adopted documentation responsibility.**
8. **One authority owner per artifact.** Parallel writable homes fail closed.
9. **A README or scaffold does not establish maturity.** Presence is evidence of bytes only.
10. **Migration requires consumers, single-write discipline, exit criteria, validation, correction, and rollback.**

The finite placement result for this revision is:

- **`PLACE`** — update the existing README in place as a containment pointer;
- **`HOLD`** — do not add substantive sensitivity guidance, executable policy, protected examples, or additional topic children here;
- **`MIGRATE`, compatibility, or retirement later** — only after one reviewed target and consumer closure exist.

No new root, canonical lane, alias, contract home, schema home, policy home, fixture home, proof home, receipt home, release home, or public surface is created.

## Minimum human sensitivity-guidance contract

A substantive sensitivity-related human document, wherever it belongs, should make the following inspectable without exposing the protected payload:

| Requirement | Minimum expectation |
|---|---|
| Stable identity | Document ID, title, version, status, owning responsibility, and supersession state |
| Scope | Operation, audience, domain, geography, time, object family, and explicit exclusions |
| Protected-interest class | Safe category or code; never the protected value itself |
| Source and evidence | Governed source/evidence references, limitations, and source role |
| Rights and consent | Exact governing references and unresolved-state behavior; never infer from absence |
| Sensitivity context | Accepted `SensitivityLabel` or equivalent reference and effective time |
| Requested exposure | Fields, geometry precision, joinability, audience, and purpose |
| Obligations | Generalize, redact, aggregate, delay, restrict, review, deny, hold, or abstain as defined by owning policy |

## Security, rights, sensitivity, and public safety

KFM's inherited posture is fail closed when rights, consent, source role, sensitivity, review, release state, correction state, or harmful precision is unresolved. Depending on the owning policy and object family, safe responses may include quarantine, denial, hold, abstention, redaction, generalization, aggregation, delayed access, staged access, or authorized review.

That posture is governance, not proof of deployed enforcement.

Public documentation must:

- describe controls without reproducing the protected fact;
- use synthetic or irreversibly generalized examples;
- avoid exact coordinates, high-resolution reconstruction clues, private joins, and real identities;
- avoid publishing transform parameters that defeat the intended protection;
- distinguish source evidence, restricted canonical objects, public derivatives, and visual carriers;
- preserve the fact that a public derivative is not the underlying evidence object;
- expose safe status and correction information without leaking protected reasons;
- require server-side policy and transformation before public delivery;
- keep raw model output and generated summaries subordinate to evidence and policy; and
- preserve correction, withdrawal, cache invalidation, rollback, and recompile obligations.

A missing value is not evidence of permission. A generalized point is not evidence that the exact point may be released. A green test is not evidence that every consumer is protected. A public map style is not a security boundary.

The current path is preserved because complete consumers and final placement are not verified. Preservation is not acceptance.

1. freeze current main, exact blobs, accepted authority, owners, consumers, active branches, and overlapping pull requests;
