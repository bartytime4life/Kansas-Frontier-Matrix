> **Start here for Habitat source-head inspection, deterministic no-live-source validation, promotion-readiness review, rollback or withdrawal preparation, and the ecoregions procedure sublane.** This directory explains how an authorized actor should orient, proceed, stop, and hand off; it does not supply the authority, evidence, policy decision, review, release decision, or public state that an operation requires.

## Purpose

`docs/runbooks/habitat/` is the Habitat domain lane inside KFM's human-readable operational-procedure root. It helps maintainers, reviewers, stewards, developers, and operators answer bounded questions before acting:

- Which Habitat procedure applies to the current task, candidate, source-head signal, validation need, or release-facing defect?
- Is that procedure repository-grounded, fixture-only, inspection-only, candidate-only, synthetic-only, held, or operationally admitted?
- Which exact repository revision, source identity, rights state, sensitivity state, evidence, policy result, review, permission, candidate record, correction route, and rollback target are prerequisites?
- Which action belongs to a connector, source registry, pipeline, validator, policy evaluator, evidence resolver, lifecycle writer, review surface, or release service rather than Markdown?
- Which condition requires `HOLD`, `ABSTAIN`, `DENY`, `ERROR`, `REVIEW_REQUIRED`, quarantine, containment, withdrawal, rollback, or escalation?
- Which immutable records and public-safe reason codes must remain inspectable after correction, supersession, withdrawal, rollback, or replay?

The directory is documentation-first. Executable behavior and trust-bearing objects remain in their owning responsibility roots. These runbooks should make the governed path usable without embedding a second source registry, contract system, schema authority, policy engine, evidence store, release plane, rollback executor, or publication path in documentation.

## Habitat operating law

### Habitat owns landscape context, not species truth

Habitat may describe land cover, ecological systems, patches, modeled suitability, quality, connectivity, corridors, restoration opportunity, stewardship context, uncertainty, and regionalization. Fauna owns animal occurrence and taxonomic evidence; Flora owns plant occurrence and specimen evidence. A Habitat runbook may require a governed join, but it must not absorb the neighbor domain's authority.

### Source role and knowledge character remain explicit

Keep these distinctions visible across procedure inputs, outputs, logs, review packets, and handoffs:

- observed land-cover or field evidence;
- regulatory designations;
- modeled classifications or suitability surfaces;
- aggregate summaries;
- administrative or stewardship context;
- candidate material;
- synthetic fixtures.

Promotion cannot upgrade one role into another. A modeled surface is not a regulatory designation. An aggregate range is not an occurrence. A context layer is not evidence of presence. A fixture is not a source.

### Representation is downstream of trust

A polygon, raster, vector tile, PMTiles archive, COG, style, popup, screenshot, graph edge, search result, Evidence Drawer summary, or AI answer is a carrier or interpretation. It does not establish source authority, evidence closure, policy approval, review, release, or publication.

### Ecoregions are regionalization context

An ecoregion polygon is meaningful only under a named framework, hierarchy level, source version, boundary version, geometry lineage, and crosswalk posture. It does not independently prove species occurrence, plant occurrence, habitat quality, legal critical-habitat status, management priority, or public-release safety.

### Sensitive joins transform before rendering

Protected precision must be redacted, generalized, aggregated, withheld, quarantined, or denied before public delivery. Client-side filtering, style opacity, hidden layers, omitted popups, or disabled controls do not protect bytes already delivered to the client.

### Public clients stay downstream of release

Normal UI, map, export, search, graph, and AI surfaces use governed APIs and released public-safe carriers. They do not read `RAW`, `WORK`, `QUARANTINE`, candidate dossiers, exact protected stores, model runtime output, or source APIs as their normal path.

## Lifecycle and state separation

The canonical lifecycle remains:

```text
RAW -> WORK / QUARANTINE -> PROCESSED -> CATALOG / TRIPLETS -> PUBLISHED
```

Runbooks explain prerequisites and handoffs around that lifecycle. They do not advance an object through it by instruction alone.

Do not collapse these independent axes:

| Axis | Example | What it does not prove |
|---|---|---|
| File presence | A runbook, source descriptor, fixture, candidate README, or manifest-shaped file exists | Correctness, acceptance, activation, review, or release |
| Documentation state | Blank, scaffold, draft, repository-grounded, corrected, or current at a pinned revision | Executable behavior or operational admission |
| Source state | Discovered, described, admitted, active, suspended, withdrawn | Evidence sufficiency, policy approval, or release |
| Validation state | Contract/schema/fixture/profile pass, fail, warning, or error | Ecological truth, rights, reviewer authority, or publication |
| Evidence state | `EvidenceRef` present, bundle resolved, support sufficient, support stale or conflicted | Policy approval or release decision |
| Policy state | Allow, restrict, hold, abstain, deny, or error under an accepted evaluator | Human review, lifecycle mutation, release, or deployment |
| Review state | Requested, pending, approved, rejected, conflicted | Release execution or publication |
| Candidate state | Draft dossier, ready for review, blocked, withdrawn | Released carrier |
| Release state | Decision and immutable manifest exist | Deployment or public exposure unless read back |
| Publication state | A public-safe carrier is exposed through governed delivery | Continued fitness after correction, withdrawal, or source change |
| Recovery state | Contained, correction proposed, withdrawal approved, rollback approved, read-back complete | Erasure of prior history or automatic source correction |

Promotion is a governed state transition, not a file move, commit, pull request, merge, workflow result, badge, candidate folder, map render, or generated summary.

## What belongs here

This directory may contain human procedures that:

- define exact triggers, prerequisites, authority pointers, safe environments, and stop conditions;
- identify repository-native commands only after those commands and their scope are verified;
- distinguish source-head inspection from source admission, fetch, transformation, and activation;
- explain deterministic synthetic fixture validation and what passing checks do not prove;
- route evidence, policy, sensitivity, geoprivacy, review, candidate, release, correction, withdrawal, and rollback handoffs;
- define finite procedure outcomes and public-safe reason-code handling;
- require exact revision, input identity, output identity, receipts, limitations, and rollback targets;
- explain cross-domain ownership without creating a cross-domain truth object in Markdown;
- document failure diagnosis, containment, correction, recovery, and review escalation;
- preserve historical evidence snapshots and supersession notes.

A new runbook or sublane requires placement review, direct-child navigation, an explicit authority boundary, verified adjacent paths, and a coherent validation and rollback story.

## Finite outcomes and stop conditions

Procedure outcomes are local classifications. They must not be confused with policy, API, lifecycle, candidate, release, or publication states.

| Outcome | Meaning | Required action |
|---|---|---|
| `PASS` | The named bounded checks passed at the exact revision | Record scope and limitations; continue only to the separately authorized next gate |
| `NO_CHANGE_CANDIDATE` | An accepted comparison profile found no material difference within declared scope | Preserve the comparison and hand off; do not claim universal freshness |
| `MATERIAL_CHANGE_CANDIDATE` | Supported differences may affect identity, role, rights, sensitivity, time, geometry, evidence, or obligations | Freeze affected work and route to accountable owners |
| `REVIEW_REQUIRED` | Evidence is ambiguous or accountable judgment is required | Stop automation and obtain the named review |
| `HOLD` | A prerequisite, authority, owner, source, profile, candidate, policy, evidence, permission, or rollback route is unresolved | Do not fetch, mutate, promote, release, or publish |
| `ABSTAIN` | A consequential claim lacks sufficient admissible support | Withhold the claim and expose a safe explanation |
| `DENY` | A known rights, sensitivity, security, policy, or trust rule prohibits the operation | Stop and preserve only safe evidence and reason codes |
| `ERROR` | Input integrity, deterministic execution, or required tooling failed | Preserve diagnostics; retry only after the cause is resolved |
| `ROLLBACK` | A separately authorized recovery decision requires restoring a safe prior state | Execute only through the accepted release/recovery path and verify read-back |
| `ESCALATE` | The issue exceeds the procedure's authority or risk boundary | Route to accountable and, where required, independent review |

### Mandatory stops

Stop rather than improvise when:

- repository revision, target bytes, or task identity cannot be frozen;
- a required source is not admitted and active;
- source role or model/observation/regulatory meaning is conflicted;
- rights, terms, citation, or redistribution obligations are unknown;
- exact or reconstructable sensitive detail could escape;
- a required EvidenceRef does not resolve to sufficient evidence;
- policy source, bundle, selector, evaluator, or decision is unaccepted or unavailable;
- a real candidate, release, correction, withdrawal, or rollback record does not exist;
- a command, fixture, test, validator, workflow, or public endpoint cannot be verified;
- concurrent work owns the same bytes or semantic authority;
- the action would write `RAW`, `WORK`, `QUARANTINE`, `PROCESSED`, `CATALOG`, `TRIPLETS`, `PUBLISHED`, release state, or public state without an authorized writer;
- rollback, correction, invalidation, or public read-back cannot be demonstrated proportionately to risk.

## Sensitivity, rights, and public-safe treatment

Habitat information ranges from low-risk regional context to highly sensitive joined knowledge. Classification must consider both the Habitat object and every relation that can reconstruct protected detail.

### Treat as potentially restricted

- exact occurrence-linked habitat geometry;
- rare-species, rare-plant, breeding, nesting, denning, roosting, hibernation, spawning, migration, or congregation context;
- stewardship, restoration, cultural, archaeological, private-land, or infrastructure relationships;
- controlled taxon attributes and source-native withheld fields;
- redaction, generalization, aggregation, displacement, or suppression parameters;
- model inputs or outputs that enable protected-location inference;
- proprietary or terms-restricted source material.

### Public-safe controls

Where release is otherwise admissible, use reviewed combinations of:

- coordinate generalization or aggregation;
- geometry clipping, cell/tile coarsening, or omission;
- temporal broadening or delay;
- attribute suppression;
- audience-based access;
- restricted EvidenceBundle pointers with public-safe summaries;
- cache and export controls;
- non-sensitive reason codes;
- correction, withdrawal, invalidation, and rollback linkage.

Every transform should retain source identity, transform identity, parameters in an appropriately restricted record, input and output digests, policy and review references, limitations, correction lineage, and rollback target. A public-safe carrier must not expose the protected input or transform secret through properties, tiles, logs, errors, URLs, screenshots, graph edges, or AI context.

Unknown rights, source terms, sovereignty, sensitivity, or harmful precision yields `HOLD`, `ABSTAIN`, `DENY`, quarantine, redaction, staged access, or non-publication according to the owning controls.
