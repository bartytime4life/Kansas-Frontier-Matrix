# `docs/runbooks/people-dna-land/` — People, DNA, and Land Operational Procedure Boundary

> **Local index for repository procedures involving people, genealogy, DNA-derived material, consent, revocation, vendor-loss rehearsal, and land-linked identity.** These documents can guide bounded repository review, synthetic validation, and synthetic-metadata tabletop exercises. They do not establish identity, kinship, consent validity, title, legal boundaries, cultural authority, source admission, source health, policy approval, operational containment, release, or publication.

> [!CAUTION]
> This is a sensitive domain. Do not place real living-person identifiers, DNA or genomic material, raw kit or vendor identifiers, credentials, private relationship data, exact private locations, protected cultural information, disputed title material, or proprietary source excerpts in Git, pull requests, issues, CI logs, fixtures, screenshots, tabletop records, or public artifacts.

> [!IMPORTANT]
> The strongest current executable evidence is two deterministic, no-network synthetic consent profiles. The DTC vendor-loss runbook is a human tabletop using synthetic metadata only; it is not an executable vendor-loss profile. Neither a passing workflow nor a successful tabletop establishes a real person's identity, kinship, consent, rights, DNA support, title, boundary, EvidenceBundle closure, active policy runtime, vendor health, operational readiness, release approval, or public-use safety.

## Inputs and outputs

### Required inputs

- Exact repository revision and affected paths.
- Named purpose, audience, data class, exposure class, and proposed action.
- Resolved source role, control, rights, provenance, sensitivity, consent, living-person, sovereignty, harmful-precision, custody, and retention posture.
- Exact applicable contracts, schemas, policy versions, evidence references, and review requirements.
- Synthetic fixtures or fictional metadata for repository-visible validation and tabletop rehearsal; no real sensitive payloads.
- Named rollback, revocation, correction, withdrawal, or containment path when the action could affect exposure.

### Permitted outputs

- A finite `PASS`, `FAIL`, `NOT_RUN`, `HOLD`, `ABSTAIN`, `DENY`, `ERROR`, `ROLLBACK`, or `ESCALATE` result with exact revision and reason, bounded to the procedure that produced it.
- A minimized reviewer handoff that contains no sensitive payload values or real vendor/account details.
- Links to test or workflow evidence at the tested SHA.
- A documentation correction or draft pull request that does not activate sources, access vendors, mutate data, approve policy, execute containment, release, deploy, or publish.

Authorized repository contributors may edit these documents through the normal reviewed Git workflow. That permission does not make an editor a privacy, consent, sovereignty, legal, source, custody, security, policy, evidence, release, operations, or publication authority.

## Exposure, mutation, and retention

- Treat this documentation and any tabletop result as repository-visible unless an approved restricted system says otherwise. Record classifications, opaque fictional references, reason codes, and minimized summaries—not sensitive values.
- Living-person and DNA-derived exposure fails closed. Unknown living status, unclear consent, disputed rights, unresolved vendor control, sovereignty concerns, harmful precision, custody uncertainty, or retention ambiguity produces `HOLD`, `ABSTAIN`, `DENY`, or `ESCALATE`, never implied approval.
- Vendor loss does not authorize emergency bulk download, custody transfer, indefinite retention, silent deletion, or public use.
- Assessor and tax records remain administrative observations, not title truth. Parcel geometry remains context, not legal-boundary proof.
- Repository-visible tests use synthetic fixtures only. Tabletop exercises use fictional metadata only. Do not copy a real source payload into either surface.
- Preserve Git history and correction lineage. A documentation edit or revert does not revoke consent, delete a source record, contain a vendor incident, withdraw a release, invalidate a cache, or reverse an operational action.

The DTC vendor-loss runbook adds a human tabletop, not a third executable profile. A successful tabletop proves only that participants followed the synthetic-only procedure and identified gaps without creating external or sensitive effects.
