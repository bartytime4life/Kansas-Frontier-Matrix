# Settlements and Infrastructure Operational Procedure Boundary

This directory routes maintainers to Settlements/Infrastructure procedures and
states the lane's current fail-closed posture. It is an index and boundary
contract, not municipal-status, census, facility, condition, service,
dependency, source, policy, evidence, proof, release, or publication authority.

> [!WARNING]
> KFM is not an emergency, public-safety, utility-service, infrastructure-
> condition, municipal-law, land-use, planning, inspection, security, legal, or
> regulatory authority. Repository files and passing checks cannot establish
> that a place is legally incorporated, a facility is safe, a service is
> available, or infrastructure is current, complete, lawful, or suitable for
> operational decisions.

> [!IMPORTANT]
> Current executable evidence contains two bounded profiles: static readiness
> checks and a no-network-compatible EvidenceBundle projection-convergence
> check. The promotion runbook can now guide preflight and accountable-review
> handoff, but no profile validates real Settlements/Infrastructure records,
> activates domain policy, produces proof, executes rollback, or establishes
> release, deployment, promotion, or publication authority.

## Purpose and inherited authority

Accepted [ADR-0029](../../adr/ADR-0029-adopt-directory-governance-standard-v2.md)
adopts the [Directory Rules](../../doctrine/directory-rules.md), which place
human operational procedures below `docs/runbooks/` and require boundaries to
inherit authority rather than manufacture it.

This README:

- distinguishes implemented readiness and schema-convergence checks from held
  domain semantic work;
- routes readers to current child procedures and responsibility roots;
- preserves settlement and infrastructure, legal and census, source-role,
  temporal, sensitivity, cultural, sovereignty, and cross-domain boundaries;
- records stop conditions for operational or public claims; and
- keeps documentation, review, release, deployment, promotion, publication,
  correction, and rollback as separate states.

It does not resolve the repository's `settlements-infrastructure`,
`settlement`, and related path variants. That remains an ADR- and
migration-dependent question.

## Static readiness

The [domain workflow](../../../.github/workflows/domain-settlements-infrastructure.yml)
performs three read-only jobs:

1. `validate-settlements-infrastructure` checks the expected structural and
   placeholder inventory, then records
   `WORKFLOW_HOLD: semantic Settlements/Infrastructure validation is not established`.
2. `build-proof-settlements-infrastructure` confirms the proof hold and records
   that no accepted deterministic proof producer exists.
3. `publish-dry-run-settlements-infrastructure` checks candidate and published
   boundaries and records that no accepted release-dry-run command or
   candidate-manifest contract exists.

Its readiness helper is:

```bash
python tools/validators/ci_readiness.py \
  --label "Settlements/Infrastructure" \
  --test-root tests/domains/settlements-infrastructure \
  --validator-root tools/validators/domains/settlements-infrastructure \
  --validator-root tools/validators/facilities \
  --validator-root tools/validators/hazard-exposure
```

This helper classifies readiness surfaces; it does not execute placeholder test
modules or validator scripts. Use the exact workflow at the reviewed commit as
the full procedure definition.

### Readiness result boundaries

A green readiness job may support only these claims:

- required boundary paths existed at the tested SHA;
- tracked JSON inspected by the workflow parsed;
- expected placeholder and held-lane sentinels behaved as written; and
- no unreviewed proof artifact, candidate record, domain target, producer
  command, or release command silently appeared.

It does not prove legal place identity, facility status, source admission,
rights, active policy, evidence closure, proof, review, release, rollback, or
public behavior.

## Bounded EvidenceBundle projection convergence

The
[convergence workflow](../../../.github/workflows/settlements-infrastructure-evidence-bundle-convergence.yml)
verifies that the domain's
[`evidence_bundle.schema.json`](../../../schemas/contracts/v1/domains/settlements-infrastructure/evidence_bundle.schema.json)
remains a projection of the
[shared EvidenceBundle schema](../../../schemas/contracts/v1/evidence/evidence_bundle.schema.json)
rather than a second semantic authority.

Run the complete guarded local procedure in
[`NO_NETWORK_TEST_RUNBOOK.md`](./NO_NETWORK_TEST_RUNBOOK.md). Its focused
commands are:

```bash
python -m unittest discover \
  --start-directory tests/validators/domains/settlements-infrastructure \
  --pattern 'test_evidence_bundle_schema_convergence.py' \
  --verbose
python tools/validators/validate_settlements_infrastructure_evidence_bundle_projection.py --fixtures
```

The profile checks:

- projection delegation to the shared schema;
- `authority: projection`, `independent_fields: DENY`, and denial of release or
  critical-infrastructure-exposure authority;
- absence of independent domain fields;
- the shared schema's closed ten-field top-level shape; and
- expected acceptance and rejection behavior over tracked shared fixtures.

The workflow sets `KFM_NO_NETWORK=1`, but it does not inject the shared Python
startup guard into `PYTHONPATH`. The environment variable alone is not
runner-wide no-egress proof. The no-network runbook provides the guarded local
procedure and explains its limits.

This profile does not establish a materialized EvidenceBundle, EvidenceRef
resolution, source authority, correct rights or sensitivity labels, active
policy, infrastructure review, proof, candidate approval, release, deployment,
promotion, or publication.

## Inputs, outputs, and failure cases

### Permitted bounded inputs

- the tracked repository tree at an exact revision;
- required boundary files named by the domain workflow;
- tracked schemas and fixtures inspected by the bounded workflows;
- the domain EvidenceBundle projection and shared EvidenceBundle schema;
- current placeholder test and validator inventories;
- documented policy, proof, candidate, and published-lane hold markers; and
- one public-safe, reference-only candidate dossier for preflight, when such a
  dossier exists under an accepted contract.

### Bounded outputs

- workflow or local-check status tied to an exact commit;
- structural-error messages for missing paths, malformed JSON, unexpected
  maturity, or held-lane drift;
- a preflight result of `PASS`, `ABSTAIN`, `DENY`, `ERROR`, or workflow
  `HOLD`; and
- at most `READY_FOR_ACCOUNTABLE_RELEASE_REVIEW` from the promotion preflight.

These outputs are not EvidenceBundles, PolicyDecisions, ReviewRecords, proofs,
PromotionDecisions, ReleaseManifests, RollbackCards, correction completion, or
published artifacts.

### Failure interpretation

| Observation | Interpretation | Required response |
|---|---|---|
| Readiness workflow is green | Expected structural and held-state checks completed at one SHA | Record the SHA and holds; do not report semantic validation or operational readiness |
| EvidenceBundle convergence is green | Projection and shared fixtures satisfied bounded checks at one SHA | Report schema convergence only |
| Convergence fails | Projection metadata, shared required fields, delegation, or fixture behavior drifted | Stop and reconcile schema authority; do not add independent domain fields by convenience |
| Placeholder classifier fails | Substantive-looking code or tests appeared without a reconciled graduation | Inspect the exact change and add required fixtures, semantics, review, and evidence before changing maturity claims |
| Proof or candidate guard fails | An unexpected artifact or command surfaced in a held lane | Quarantine and review it; do not infer proof, release, or publication authority |
| Promotion preflight returns `READY_FOR_ACCOUNTABLE_RELEASE_REVIEW` | One dossier appears complete enough for human review | Hand it off; do not approve, release, deploy, promote, or publish |
| A proposal-era command happens to run | One illustrative command executed in one environment | Do not upgrade the rollback or source-refresh runbook or generalize beyond the exact evidence |

## Safety, rights, and cross-domain boundaries

Settlements/Infrastructure material can expose critical assets, facility
interiors, dependencies, condition observations, service gaps, private-
property context, living-person proximity, reservation communities,
culturally significant places, archaeological locations, and harmful
precision. Apply the most restrictive supported exposure and stop when rights,
sovereignty, consent, sensitivity, source role, time, freshness, geometry
lineage, uncertainty, or correction status is unresolved.

Keep these concerns separate:

- legal municipalities are not interchangeable with census places, named
  places, post offices, historic townsites, communities, or map labels;
- a facility record is not proof of ownership, operation, condition, capacity,
  availability, safety, access, or current status;
- generalized public geometry does not replace restricted canonical geometry;
- Roads/Rail/Trade, Hazards, Hydrology, People/DNA/Land, Archaeology, legal,
  emergency, safety, and regulatory claims retain their own authority; and
- maps, indexes, schemas, tests, workflows, dashboards, and generated text are
  not sovereign truth.

Do not place credentials, temporary source URLs, restricted payloads, facility
interiors, dependency graphs, exploitable condition detail, precise sensitive
coordinates, private-person detail, or unreviewed source excerpts in runbooks,
pull requests, logs, or fixtures.

## Stop conditions

Stop and return `HOLD`, `ABSTAIN`, `DENY`, `ERROR`, or `ESCALATE` as supported
when any required item is unresolved:

- exact revision, command, schema or contract pairing, fixture set, or expected
  negative outcome;
- source identity, source role, rights, license, cadence, currentness, legal
  authority, retrieval context, or valid time;
- settlement, facility, operator, observation, service, dependency, geometry,
  or cross-domain identity;
- policy, sensitivity, infrastructure-security, cultural, sovereignty,
  archaeology, privacy, or accountable reviewer authority;
- evidence, proof, manifest, release decision, correction path, invalidation
  plan, or rollback target; or
- public-safe interface, release, deployment, promotion, or publication state.

Never weaken a schema check, placeholder guard, no-network boundary, policy
hold, proof hold, release hold, negative fixture, or topology ratchet to obtain
a passing result.

## Maintenance

When this lane changes:

1. Verify commands and paths against current workflow and repository bytes.
2. Update this maturity table when a child procedure, fixture index, test suite,
   validator family, policy runtime, proof producer, or release control changes.
3. Keep the remaining proposal-era rollback and source-refresh runbooks
   explicitly bounded until their full procedure contracts are reconciled.
4. Preserve legal and census identity, source-role, temporal, sensitivity,
   cultural, sovereignty, cross-domain, correction, and rollback separation.
5. Keep semantic, schema, policy, source, evidence, proof, lifecycle, release,
   and executable changes in their owning roots.

[CODEOWNERS](../../../.github/CODEOWNERS) to `@bartytime4life`. That route does
not establish domain expertise, independent review, policy approval, source
admission, release, deployment, promotion, or publication.
