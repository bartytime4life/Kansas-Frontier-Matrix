## 4. Proposed Labette County proof slice

The sibling plan proposes a **Big Hill Public-Use and HAER
Defense-Industrial Context** proof slice. Its central test is whether KFM can
present bounded recreation/project and documentary industrial-history context
without becoming a present operational, environmental, property, health, or
safety authority.

### Plan-defined public-safe composition

| Candidate component | Bounded future use | Required limit |
|---|---|---|
| `OperationalEnvironmentalBoundaryNotice` | Explain what the composition cannot establish and why | Must never disclose operational detail or imply an environmental, health, compliance, property, or safety verdict |
| `BigHillProjectPurposeCard` | Carry a narrow, source-attributed description of plan-recorded project purposes | No live level, closure, flood, swimming, access, or emergency conclusion |
| `BigHillPublicUseContextCard` | Offer time-bounded public-use context and a verified official linkout | No “open,” “safe,” or “available now” claim from a static page |
| `HAERDefenseIndustrialHistoryCard` | Present documentary engineering and industrial-history context | Historic only; no present operation, capability, vulnerability, contamination, ownership, or access inference |
| Labette county orientation extent | Bound the map and question scope | Requires authoritative geometry, vintage, rights, simplification, and no parcel inference |
| County official-information linkout | Route users to an official civic surface | Linkout is not ingestion, title evidence, emergency advice, or public endorsement |
| Current environmental or remediation card | Possible later, source-specific regulatory context | `DEFER` until a fit current authority, rights, claim scope, review, and correction path are established |
| Generalized ecology context | Possible later public-safe habitat or fish-and-wildlife context | `DEFER` pending ecology authority, geoprivacy, closure, and generalization review |
| Facility-detail or vulnerability layer | None in the public proof slice | `DENY` |
| Parcel/title/access layer | None in the public proof slice | `DENY` |
| Live lake-safety, closure, flood, or emergency layer | None in a static county composition | `EXCLUDE`; use official-current routing only |

### Product promises and non-promises

| The proposal may eventually promise | It must not promise |
|---|---|
| a bounded Labette spatial frame backed by an admitted geometry source | parcel identity, title, ownership, or permission to enter |
| evidence-visible project/public-use and documentary-history context | present facility mission, capability, occupancy, security, or vulnerability |
| explicit source-role and time-basis badges | contamination, exposure, health, compliance, cleanup, or clearance conclusions |
| a prominent operational/environmental boundary panel | current lake level, beach status, recreation safety, flood condition, or emergency advice |
| finite `ANSWER`, `ABSTAIN`, `DENY`, and `ERROR` states | a hidden fallback from missing evidence or policy to generated prose |
| correction and rollback references before any public release | release, deployment, or publication merely because documentation or tests exist |

### Map, evidence, and AI boundary

```text
released public-safe county context
  -> governed API
  -> bounded map and time context
  -> EvidenceRef resolution
  -> EvidenceBundle + source-role + rights + policy checks
  -> ANSWER | ABSTAIN | DENY | ERROR
  -> visible citations, limitations, stale state, correction, and release state
```

The browser, map renderer, search index, story card, and AI adapter remain
downstream carriers. None may read internal lifecycle stores or substitute for
evidence, policy, review, release, correction, or rollback.

## 5. Public safety, sensitivity, and finite outcomes

### Plan-carried guardrails

The reason codes below are **proposal vocabulary from the sibling plan**. They
are useful fixture seeds, not accepted policy or runtime constants.

| Claim or request class | Required bounded posture | Proposed reason code |
|---|---|---|
| Historic record used to claim present facility operation or capability | `ABSTAIN` or `DENY`, depending on requested specificity | `HISTORIC_RECORD_NOT_CURRENT_OPERATION_STATUS` |
| Facility layout, hazardous storage, emergency access, weak points, or vulnerability | `DENY` without returning the protected detail | `OPERATIONAL_VULNERABILITY_DETAIL_DENIED` |
| Contamination, exposure, health, compliance, cleanup, or environmental-clearance verdict without fit current authority | `ABSTAIN` or `DENY` | `ENVIRONMENTAL_HEALTH_VERDICT_UNSUPPORTED` |
| Present lake level, closure, swimming, recreation, flood, or access safety from static context | `ABSTAIN` and use a verified official-current route when configured | `LIVE_RECREATION_SAFETY_REQUIRES_CURRENT_AUTHORITY` |
| Emergency response or “what should I do now?” request | `ABSTAIN`; KFM is not an emergency authority | `OFFICIAL_EMERGENCY_GUIDANCE_REQUIRED` |
| Parcel ownership, title, or permission-to-enter determination | `DENY` | `PARCEL_OR_ACCESS_DETERMINATION_DENIED` |
| Exact or sensitive ecology detail without admitted public-safe support | `DENY` | `SENSITIVE_ECOLOGY_DETAIL_NOT_ADMITTED` |
| Public reuse of documentary assets before rights review | `ABSTAIN` or quarantine the asset | `RIGHTS_CLEARANCE_UNRESOLVED` |
| Generated text used as evidence | `ERROR` or release block | `AI_NOT_EVIDENCE` |
| Public payload points to `RAW`, `WORK`, or `QUARANTINE` | `ERROR` or release block | `PUBLIC_INTERNAL_LIFECYCLE_ACCESS` |

### Finite response contract

| Outcome | Minimum condition | Labette example | Required visible state |
|---|---|---|---|
| `ANSWER` | Resolved evidence, fit source role, allowed policy, valid citation, and appropriate release state | A narrow explanation of an admitted historic-documentary or project-purpose claim | sources, time basis, limitations, policy/release state, correction path |
| `ABSTAIN` | Evidence, currentness, rights, source fitness, or scope is insufficient | Present lake safety or current facility-status question cannot be supported | reason code, evidence gap, official-current route when verified |
| `DENY` | Request crosses operational-security, property, sensitive ecology, or prohibited exposure boundary | Request for vulnerabilities, hazardous layout, parcel access, or protected detail | bounded reason and obligations without leaking the denied material |
| `ERROR` | Contract, resolver, validator, policy, citation, or runtime failure prevents a trustworthy result | Evidence reference cannot resolve or a public payload leaks an internal path | stable error code; no guessed fallback answer |

### Required negative-state behavior

- A refusal panel must explain the bounded reason without repeating protected
  facility, property, health, or ecological detail.
- A stale or static source must never silently answer a live-status question.
- A historic/documentary source must carry an unmistakable historic time basis.
- A current-authority linkout must not be presented as a KFM determination.
- Missing rights, evidence, policy, review, correction, or rollback state must
  fail closed at the operation whose safety depends on it.
- The UI must keep `NOT_RELEASED`, `ABSTAIN`, `DENY`, `ERROR`, stale, and
  restricted states visible rather than converting them into empty or optimistic
  content.

## 6. Source role, rights, and currentness boundary

The sibling plan records five official public source checks dated 2026-05-24.
They remain dated research leads in this README. Public availability and prior
inspection do not constitute source admission, rights clearance, evidence
closure, or release eligibility.

| Plan-named source family | Plan-carried role | May support after admission | Must not support by inference |
|---|---|---|---|
| U.S. Army Corps of Engineers Big Hill pages | Federal project-purpose and public-use context; possible official-current routing | bounded project/public-use context with checked date and limitations | current lake level, closure, swimming safety, flood safety, access, emergency, or facility-vulnerability judgment |
| Library of Congress / HAER record | Documentary historic and engineering record with an explicit rights-review concern | historic/documentary context and rights-aware metadata | current operations, security, contamination, exposure, health, compliance, ownership, access, or clearance |
| Labette County GIS and parcel routing | Local administrative/property-source surface | existence of an official routing surface or an exclusion explanation | title, ownership, permission to enter, living-person joins, environmental condition, or infrastructure exposure |
| Labette County Emergency Management | Official local emergency-function and redirect surface | agency-function context and a verified official-current route | cached alert, incident interpretation, personal emergency guidance, or KFM safety determination |
| Later environmental or regulatory source | Candidate regulatory/environmental role only after admission | narrowly scoped, time-bounded official context if rights, fitness, review, and correction close | household health claim, legal conclusion, blanket clearance, or extrapolation beyond source scope |
| Generated AI narrative | Downstream evidence- and policy-bounded explanation | summary of already resolved and allowed evidence | source truth, review, rights, policy decision, release approval, or publication authority |

### Temporal classes must remain separate

| Temporal class | Example in the proposed slice | Required handling |
|---|---|---|
| Historic documentary record | HAER industrial-history material | show documentary/historic date and prohibit current-status inference |
| Stable project context | plan-recorded project-purpose material | show source check/as-of basis and limit the claim to stable project context |
| Dynamic operational status | lake closure, recreation safety, flood, emergency, facility operation, regulatory status | require a fit official-current source, freshness rule, expiry, correction, and fail-closed behavior |
| Generated interpretation | AI or narrative summary | bind to evidence and time scope; never give it independent currentness |

### Rights and sensitive-detail posture

Before any documentary image, map, scan, facility representation, parcel
attribute, or ecology feature becomes public, the responsible review must
establish:

1. source identity and allowed use;
2. asset-level rights and attribution obligations;
3. operational, infrastructure, property, environmental, ecology, and
   reidentification risk;
4. necessary redaction, generalization, omission, or staged access;
5. evidence and policy references;
6. review, release, correction, withdrawal, and rollback support.

An unresolved item belongs in `WORK` or `QUARANTINE`, not in a public map,
drawer, export, search result, or AI answer.

candidate is a **no-network synthetic Labette boundary profile**, not a live
connector, public map, or source activation.

- one bounded `ANSWER` candidate for admitted-looking **synthetic** project or
  historic context;
- one `ABSTAIN` candidate for a live lake, emergency, current-operation, or
  current environmental question that lacks fit current evidence;
- one `DENY` candidate for operational vulnerability, parcel/access, protected
  ecology, or prohibited exposure detail;

  internal-lifecycle-path leakage.
