# Osage County Focus Mode Documentation Boundary

> **Purpose.** Explain the repository-present Osage County planning lane and the
> evidence, property/GIS, hydrology, floodplain, cultural-heritage, archaeology,
> ecological, infrastructure, review, correction, and rollback conditions that
> must remain visible before any Osage County Focus Mode can become more than a
> proposal.

> [!IMPORTANT]
> **This directory contains documentation, not a released county product.** The
> sibling build plan and this README do not admit a source, create an
> `EvidenceBundle`, activate county policy, implement a governed API route,
> approve a map or AI answer, or create release or publication state.

> [!CAUTION]
> **Placement remains a compatibility HOLD.** Accepted ADR-0029 adopted the
> current Directory Rules v2 bytes and made `docs/doctrine/directory-rules.md`
> the writable human placement authority. This README stays at the existing
> singular, snake_case path. ADR-0027 remains proposed and cannot authorize a
> second plural/kebab county lane or a migration through inference.

> [!WARNING]
> **Public GIS availability is not permission to overclaim.** Parcel maps,
> appraiser-facing records, floodplain references, project pages, wildlife data,
> cultural-history interpretation, archaeology, infrastructure, and generated
> language must not be collapsed into title truth, emergency guidance, exact
> sensitive-place disclosure, vulnerability intelligence, living-person
> profiling, or authoritative cultural meaning.

### This README owns

- a human-readable explanation of the current Osage county directory;
- links to the tracked sibling plan and relevant repository authority surfaces;

| Authority or object family | Owning surface or decision class | Osage effect |
|---|---|---|

| Allow, deny, abstain, restriction, or release admissibility | `policy/` plus accountable review | It records expected fail-closed behavior but makes no policy decision |
| Runtime implementation and governed public routing | Application, package, and runtime owners | No Osage API, evidence resolver, renderer, or model adapter is created |

| Promotion, release, correction, withdrawal, and rollback decisions | `release/` and accepted review authority | A branch, pull request, check, or merge cannot perform these transitions |

owned elsewhere; it must not copy those objects into a county-local parallel authority.

## 4. Proposed Osage County proof slice

The sibling plan proposes a county slice that connects **property-facing GIS,
Marais des Cygnes watershed and floodplain context, agriculture, geology and
groundwater, U.S. 75 / K-31 transportation context, settlement history, and
public-safe cultural heritage** while keeping each source role distinct.

### Plan-defined public-safe themes

| Theme in sibling plan | Bounded future use | Required limit |
|---|---|---|
| County and municipal context | General public place orientation | No owner/person dossier or legal status inference |
| Marais des Cygnes / watershed / floodplain context | Time- and source-labeled hydrologic education | No emergency warning, insurance advice, or property-specific flood determination |
| Agriculture and soil | County-scale aggregate and landscape context | No producer, parcel, yield, private-well, or causation inference |
| Geology / groundwater | Educational county-scale interpretation with source scale and limitations | No construction, contamination, well-yield, or drinking-water assurance |
| U.S. 75 / K-31 and route context | Generalized movement/project/history context | No real-time routing promise or vulnerability detail |
| Settlements and services | Public-safe place and service-area context | No sensitive facility or security exposure |
| Cultural heritage / archaeology | Reviewed public interpretation only | No exact sacred, burial, archaeological, artifact, or restricted geometry |
| Habitat / fauna / flora | Generalized ecological context | No precise rare-species, nest/roost, collection, or sensitive management detail |

### Product and authority boundary

A future Osage Focus Mode may become map-rich and evidence-visible only after
relevant objects are admitted, validated, policy-reviewed, released, and
correction-ready. The current README and plan cannot create that state.

## 5. Public safety, sensitivity, and finite outcomes

### 5.1 Required public outcome posture

| Request or condition | Expected bounded result | Why |
|---|---|---|
| General released county landscape question with resolved evidence | `ANSWER` | Released, in-scope evidence can support a bounded explanation |
| Missing, stale, or conflicting floodplain/project/source state | `ABSTAIN` | Currentness or authority is insufficient |
| Property-specific flood/title/insurance/legal determination | `ABSTAIN` or `DENY` | KFM is not the responsible legal or administrative authority |
| Parcel owner or living-person profile request | `DENY` | Living-person/property privacy boundary |
| Exact archaeology, burial, sacred, artifact, or culturally restricted location | `DENY` | Cultural sensitivity, sovereignty, looting, and harm risk |
| Exact rare-species occurrence or sensitive habitat intelligence | `DENY` or generalized response | Geoprivacy and conservation risk |
| Vulnerable infrastructure or security-relevant detail | `DENY` | Public-safety and security boundary |
| Live emergency flood, evacuation, or road-safety decision | `ABSTAIN` and route to responsible authority | KFM is not an emergency authority |
| Resolver, policy, source adapter, or runtime failure | `ERROR` | Failure must not silently become allow |

### 5.2 Cross-layer reconstruction rule

Individually public attributes can become sensitive when combined. A future Osage
release must evaluate whether parcel geometry, addresses, appraisal context,
infrastructure, wildlife, cultural history, hydrology, or other layers allow a user to
reconstruct a protected person, property, site, occurrence, or vulnerability.

When reconstruction risk is not acceptably bounded, KFM must generalize, redact,
stage access, abstain, or deny rather than expose the join.

### 5.3 AI boundary

AI may summarize **released and policy-safe** Osage evidence. It must not:

- infer owner identity or title status from parcel/appraiser surfaces;
- decide floodplain administration, insurance, permit, legal, or emergency outcomes;
- identify likely unlisted archaeological or sacred sites;
- infer rare-species locations from habitat context;
- expose infrastructure vulnerabilities;
- convert a stale project page into a current condition;
- speak for a Nation, community, agency, or reviewer whose authority is not established;
- treat generated language as evidence, proof, review, release, or publication authority.

## 6. Source role, rights, and currentness boundary

The sibling plan names multiple source families. Their presence in planning material
means **candidate use only** until KFM source admission, rights, sensitivity, and
release checks are complete.

| Source family in plan | Intended role | Must not be treated as |
|---|---|---|
| County/appraiser/local GIS | Administrative and parcel-reference context | Title truth, ownership proof, living-person dossier, or license for unrestricted joining |
| KDA / FEMA floodplain sources | Effective/draft floodplain and mapping context | Emergency warning, insurance determination, or timeless regulatory statement |
| KDOT / transportation sources | Road class, project, and corridor context | Real-time routing guarantee or vulnerability authority |
| USDA / agricultural sources | County-scale statistical or land-cover context | Farm/person profile, parcel causation, or individual producer truth |
| KGS | Geology and groundwater interpretation | Site-engineering, contamination, well-yield, or health authority |
| NPS / KSHS / public-history sources | Public historic interpretation | Complete cultural sovereignty, sacred-place, burial, or archaeology authority |
| KDWP / ecological sources | General public habitat/recreation context | Permission to expose sensitive occurrences or management vulnerabilities |
| eBird / GBIF or similar aggregators | Candidate observation summaries when terms and geoprivacy permit | Primary authority or unrestricted exact occurrence distribution |

### Source-currentness rule

For any source whose meaning can change—floodplain status, road projects, closures,
water conditions, public access, ecological records, or administrative data—a future
KFM object must preserve retrieval/validity time and source version appropriate to the
claim. A dated plan observation cannot be copied into durable present-tense prose.
