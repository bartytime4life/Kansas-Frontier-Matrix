## Source-role anti-collapse

A future Comanche slice must keep source roles explicit rather than combining every official page into one undifferentiated authority.

| Source family named in the plan | Permitted planning role | Must not be treated as |
|---|---|---|
| Comanche County public administration | Administrative orientation and responsible-service routing | Geology authority, title adjudicator, emergency instruction, cultural authority, or release approval |
| City of Coldwater / Lake Coldwater material | Municipal civic and broad recreation context | Live lake-safety, closure, access, fee, permit, or facility-availability service |
| Kansas Geological Survey / GeoKansas | Scientific and educational geological context | Exact public locality inventory, parcel hazard prediction, mineral/access advice, or operational warning system |
| Kansas Department of Transportation archived maps | Dated official cartographic context | Current routing, road condition, access permission, or emergency-travel authority |
| FEMA flood products and source routes | Federal flood-product authority and version routing | Individual emergency, insurance, legal, or site-safety verdict |
| Kansas Water Office and USGS routes | Candidate water-program and observation source discovery | Verified Comanche observation, jurisdiction, live safety, or legal conclusion without admitted local evidence |
| Appropriate Comanche Nation or cultural authority | Required future authority for cultural interpretation | A role that county naming prose, generated text, or unrelated official sources can substitute for |
| Generated narrative, cards, maps, and AI output | Downstream interpretation over released evidence | Evidence, policy decision, review approval, or publication authority |

Public availability, official branding, coordinates, or map detail does not by itself authorize KFM to cache, transform, tile, spatially amplify, combine, or release source material.

## Trust path and finite outcomes

A public Comanche County claim would need to follow the established KFM trust direction:

```text
source candidate
  -> RAW capture
  -> WORK / QUARANTINE review
  -> PROCESSED role-aware object
  -> EvidenceRef -> EvidenceBundle
  -> CATALOG / TRIPLETS projection
  -> policy + validation + review + release decision
  -> PUBLISHED public-safe artifact
  -> governed API
  -> Explorer presentation
```

The map, UI, county index, catalog, AI response, and this README are downstream or interpretive surfaces; none is sovereign truth.

| Outcome | Meaning |
|---|---|
| `ANSWER` | Evidence, policy, citation, time, precision, release, and consumer requirements all permit the bounded claim. |
| `ABSTAIN` | Evidence, freshness, authority, rights, geometry, cultural standing, currentness, or release support is insufficient. |
| `DENY` | The request conflicts with sensitive-locality, land/access, hazard-inference, safety, rights, trust-membrane, or release controls. |
| `ERROR` | Required object shape, resolver, validator, policy evaluator, or governed service failed; do not degrade into an unsupported answer. |

`HOLD` remains a governance/workflow state rather than a public answer. The plan also uses `DEFER` and `EXCLUDE` for candidate-scope decisions; they do not replace the runtime finite outcome set.
