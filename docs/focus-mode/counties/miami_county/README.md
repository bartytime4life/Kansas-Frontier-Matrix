> [!IMPORTANT]

> product.** The build plan and this README do not admit a source, create an

## 4. Proposed Miami County proof slice

The plan proposes a reservoir–watershed–growth-edge slice connecting public
Hillsdale Lake context, county agriculture, Osage Cuestas geology, K-68 project
context, and publicly interpreted Osawatomie history. Its value is not a parcel,
dam-operations, flood-warning, live-road, private-resource, or sensitive-site
map. Its value is proving that distinct source roles can support a bounded public
story without being collapsed into one truth layer.

| Proposed element | Intended value | Required boundary | Status |
|---|---|---|---:|
| County frame and public places | Orientation and bounded map extent | Not parcel/title/access evidence | `PROPOSED` |
| Hillsdale Lake public-context card | Explain reviewed public benefits and setting | No operations, security, vulnerability, or emergency detail | `PROPOSED` |
| Lake–watershed explainer | Show a reviewed hydrologic relationship | No forecast, warning, route, or site-specific risk claim | `PROPOSED` |
| Agriculture aggregate card | Show dated county-scale context | No farm/operator/parcel joins or inference | `PROPOSED` |
| Osage Cuestas geology card | Explain county landscape and bedrock context | No parcel suitability, quarry, mineral, title, or value conclusion | `PROPOSED` |
| K-68 project card | Explain dated project context | No present closure, detour, access, or traffic claim | `PROPOSED` |
| Osawatomie public-history node | Present a cited, publicly interpreted place | No undisclosed cultural/archaeological inference | `PROPOSED` |
| Evidence Drawer | Expose source role, dates, limits, policy, release, correction, and rollback posture | Evidence and policy authority remain elsewhere | `PROPOSED` |

### Non-goals

- no public parcel-owner or title explorer;

## 5. Source role, rights, and temporal fitness

The plan records source candidates and observations from 2026-05-21. This
README preserves their roles without recertifying the external claims.

| Plan source family | Candidate role | What it may support after admission | What it cannot prove alone |
|---|---|---|---|
| Miami County GIS/Mapping | Administrative GIS context | Availability and bounded public orientation | Title, access, public necessity, or safe owner display |
| USACE Hillsdale material | Public infrastructure/recreation context | High-level public setting and reviewed benefits | Operations, security, emergency, or drinking-water status |
| USGS monitoring location | Observation-source candidate | Timestamped released variables with qualifiers | Warning, forecast, hazard, or reservoir-management advice |
| KDA-DWR flood-planning material | Published planning analysis | Its stated study purpose and limitations | Present road passability or evacuation routing |
| KDA/USDA aggregate statistics | Dated aggregate record | County-scale measures with reference year | Farm identity, parcel use, operator behavior, or forecast |
| KGS geology material | Scientific interpretation | County-scale geology and landscape context | Engineering suitability, mineral ownership, or quarry siting |
| KDOT project page | Dated project context | Reported scope/status with retrieval time | Current traffic, detours, access, or property impacts |
| Osawatomie public interpretation | Public-history context | Cited narrative for a public site | Hidden sites, archaeology, burial, or cultural authority |

Before any candidate becomes operational, record source identity, authority,
role, terms, rights, attribution, access method, temporal character, precision,
sensitivity, citation, correction behavior, and release eligibility. Unknown
rights or safe precision mean quarantine, abstention, generalization, or denial.

### Temporal rules

Keep reported, observed, published, retrieved, valid, release, correction, and
supersession times distinct. In particular:

- a dated agriculture aggregate is not current farm activity;
- a monitoring observation is not a warning or forecast;
- a planning analysis is not current road status;
- a project page becomes stale and may be corrected or superseded;
- historical interpretation is not a current legal, access, or cultural decision.

## 6. Property, infrastructure, and current-safety boundaries

| Request or inference | Safe default | Reason |
|---|---|---|
| Show parcel owners, living-person details, assessed-value narratives, title, or private access | `DENY` or omit | Unnecessary privacy/property exposure; GIS is not title truth |
| Explain dam controls, operations, security, vulnerabilities, or tactical response | `DENY` | Critical-infrastructure and public-safety boundary |
| Decide whether a road is passable or safest now from planning/project material | `ABSTAIN` and route to current authority | Dated context is not current operational evidence |
| Infer flood, permit, insurance, emergency, or site-specific risk | `ABSTAIN` | The product is not adjudicatory or operational |
| Expose exact species, nests, habitats, sacred/burial/cultural sites, or inferred site potential | `DENY` or reviewed generalization | Ecological harm, sovereignty, cultural sensitivity, and looting risk |
| Identify parcel quarry/mineral potential, engineering suitability, or land value | `ABSTAIN` or `DENY` | False precision and private-resource inference risk |
| Join agriculture, geology, GIS, water, transport, infrastructure, and ecology at parcel scale | `HOLD` pending explicit review; normally deny | Reidentification, profiling, legal, and cumulative-risk concerns |
| Load RAW, candidate, restricted, unreleased, or direct-model data into public UI | `DENY` / `ERROR` | Trust-membrane violation |

> [!NOTE]
> A public source can still contain fields unsuitable for KFM's ordinary public
> product. Availability does not erase minimization, sensitivity, rights, or
> fitness-for-use review.

## 7. Finite outcomes and reason-code guidance

The reason codes below are **candidate documentation vocabulary**, not verified
implemented enums.

| Outcome | Use when | Candidate reason-code family |
|---|---|---|
| `ANSWER` | Released, current-enough, policy-safe evidence supports the bounded claim | `SUPPORTED_PUBLIC_CONTEXT` |
| `ABSTAIN` | Evidence, time, scope, authority, or fitness is insufficient | `EVIDENCE_UNRESOLVED`, `CURRENT_STATUS_UNSUPPORTED` |
| `DENY` | The request would expose protected, sensitive, private, or operational detail | `PROPERTY_OR_PERSON_EXPOSURE`, `INFRASTRUCTURE_SENSITIVE_DETAIL`, `SENSITIVE_LOCATION` |
| `ERROR` | Resolver, policy, citation, release, or runtime processing fails | `EVIDENCE_RESOLVER_ERROR`, `POLICY_EVALUATION_ERROR` |

Representative cases:

| Request | Outcome | Safe explanation posture |
|---|---:|---|
| “Why does Hillsdale Lake matter to the county?” | `ANSWER` only after release | Cited public context; no operational detail |
| “Who owns the parcels around the lake?” | `DENY` | Owner detail is outside the public product |
| “Is this road safe from flooding right now?” | `ABSTAIN` | Planning context is not current conditions; route safely |
| “How is the dam operated during an event?” | `DENY` | Operational/security detail withheld without elaboration |
| “Show exact sensitive wildlife or hidden sites.” | `DENY` | Geoprivacy/cultural-location boundary |
| “Which parcel has quarry potential?” | `ABSTAIN` or `DENY` | County geology cannot support private-resource inference |
| Evidence resolver or policy service unavailable | `ERROR` | Fail closed; do not invent a fallback answer |

A denial should expose the least information necessary. It must not reveal the
protected fact through its reason, tooltip, URL, export, cache, or AI explanation.

## 12. Maintenance, migration, correction, and rollback

### Maintenance triggers

Revisit this README when the sibling plan, Focus placement, a Miami source,
public-safe property/lake/infrastructure treatment, Focus contract/schema/policy/
validator/runtime authority, county index, or any Miami evidence/release/
correction/rollback object changes.

### Migration rule

Do not copy this README or plan into a new Focus tree and leave both writable. A
future migration must have an accepted decision, one canonical target, verified
consumers, preserved history and identity, repaired inbound references, defined
redirect/alias exit criteria, zero parallel writers, and a rollback plan that
does not recreate two authorities.

### Correction rule

Correct repository facts against current immutable evidence. Correct external
claims only after authoritative re-verification and record the effective date,
affected claims, public carriers, and supersession relationship. Do not silently
rewrite historical evidence or hide a correction behind a cache or summary.

### Rollback

Before merge, abandon or close the feature branch and draft pull request. After
merge, use a transparent revert or forward-fix PR against the actual merged
commit. Revert this README and its generated provenance receipt together when
the receipt binds these bytes. Never rewrite shared history.

A Git revert restores repository bytes; it would not complete correction of a
later public product. That would require governed withdrawal, supersession,
cache invalidation, correction notices, and public-state review.
