# Bourbon County Focus Mode

> **Purpose.** Orient maintainers to the Bourbon County planning lane, make its floodplain, property, transportation, mined-land, infrastructure, and cultural-context boundaries visible, and route future work through KFM evidence, policy, review, release, correction, and rollback controls.

> [!IMPORTANT]
> **Tracked planning artifacts are not implementation or release evidence.** This directory contains this README and one Bourbon County build plan. Their presence prevents accidental duplicate planning; it does not establish source admission, semantic correctness, validator success, runtime behavior, release, deployment, or publication.

> [!CAUTION]
> **Placement remains unresolved.** This same-path update repairs an existing README under `docs/focus-mode/counties/bourbon_county/`. Accepted Directory Rules v2 treats Focus Mode as a composition scope; proposed ADR-0027 describes a different plural, kebab-case control plane but remains unaccepted. No file is moved, renamed, copied into a parallel tree, or declared the final canonical county write target here.

> [!WARNING]
> **The build plan combines public context with sensitive or high-consequence subjects.** Registered-access property data, parcel-linked living-person information, exact cultural or burial locations, exact mine or infrastructure vulnerability, operational road or work-zone detail, and property-specific flood-risk claims must not reach an ordinary public client. Missing evidence, rights, safe resolution, policy, review, or release closure must produce a bounded `ABSTAIN`, `DENY`, or `ERROR` result rather than a fluent inference.

## 4. Proposed Bourbon County proof slice

The build plan proposes a public-safe county evidence cockpit centered on Fort Scott, the Marmaton River and floodplain, official county GIS and property-data boundaries, agriculture, U.S. 69 and U.S. 54 context, Pennsylvanian geology and coal or mined-land interpretation, and carefully bounded public history. That is a **planning thesis**, not a verified current product.

| Proposed element | Evidence needed before reliance | Non-effect of this README |
|---|---|---|
| County, Fort Scott, and municipal orientation | Registered authoritative geography source, vintage, geometry identity, rights, and released public-safe carrier | Does not declare a current boundary artifact or public layer |
| County GIS and online-map index | Verified official source identity, access terms, rights, freshness, field-level sensitivity, and permitted transform role | Does not admit, scrape, mirror, or publish county GIS data |
| Parcel and KSCAMA boundary | Public-versus-registered access review, living-person and property policy, source terms, field minimization, and anti-title-claim tests | Does not make ownership, legal boundary, appraisal, survey, or title assertions |
| Marmaton River and floodplain context | Separate regulatory, observed, modeled, forecast, and hydrography source roles; valid time; limitations; policy and release evidence | Does not provide emergency advice, insurance guidance, or property-specific risk |
| Aggregate agriculture and land cover | Admitted aggregate source, measure definitions, vintage, transform receipt, and anti-reidentification review | Does not authorize farm-specific inference or convert land cover into ownership or compliance claims |
| Geology, coal, and mined-land context | Appropriate geology or mining-history source role, scale, time, rights, public-safety review, and educational limitations | Does not identify current hazards, private liability, engineering fitness, or exact vulnerable infrastructure |
| Transportation corridors and projects | Current public source, project date and status, corridor scale, stale-state handling, and operational-sensitivity review | Does not provide routing, work-zone operations, enforcement, or vulnerability analysis |
| Fort Scott and broader heritage interpretation | Source authority, rights, temporal scope, cultural review, public-safe geometry, limitations, and correction path | Does not disclose exact sensitive sites, burials, protected locations, or convert public interpretation into archaeology authority |
| Map and AI interpretation | Released public-safe carriers, resolvable EvidenceBundles, finite policy outcomes, governed runtime, correction, and rollback support | Does not create a layer, route, model capability, or public answer |

The plan's recommended first milestone is a no-network, fixture-only source-index and evidence-payload dry run. That milestone remains **PROPOSED**. No source descriptor, synthetic payload, MapLibre layer, governed API route, policy decision, release manifest, or rollback rehearsal is created by this README.

## 5. Source-role and cross-domain boundaries

The build plan names several source families that answer different questions. They must not be merged into one undifferentiated county truth layer.

| Planned source or object class | Legitimate bounded role | Must not be treated as |
|---|---|---|
| County GIS or public online map | Source discovery, public map context, and candidate geometry or attribute inventory after rights review | Automatic reuse permission, title authority, evidence closure, or public release |
| Parcel, appraisal, or KSCAMA surface | Property-administration context under explicit public-access and privacy constraints | Legal title, survey, ownership certainty, living-person profile, or public registered-user dataset |
| Floodplain and hydrology sources | Distinct regulatory, observed, modeled, forecast, and hydrography context with time and source-role labels | One interchangeable flood truth, emergency authority, property safety determination, or insurance advice |
| USDA, KDA, CDL, or related agriculture material | Aggregate statistics, source-specific land-cover observations, and released derived summaries | Farm identity, private operation inference, causation, compliance, or parcel truth |
| KGS or other geology and mined-land material | Geologic units, public educational context, historical mining interpretation, and reviewed generalized carriers | Current hazard determination, engineering advice, private liability, or exact operational vulnerability |
| KDOT or other transportation material | Public corridor and dated project context | Live routing, work-zone instruction, enforcement status, or infrastructure weakness analysis |
| NPS, historical, local, or cultural source | Source-specific public history and interpretive context | Archaeological proof, exact burial or sacred-site authority, or permission to expose protected geometry |
| Generated map, Story Node, summary, or AI answer | Downstream interpretation of released, cited, policy-safe evidence | Evidence, policy, review, release, or source authority |

Cross-domain composition must preserve the identity, time basis, scale, uncertainty, rights, and limitations of every input. Spatial proximity among a parcel, floodplain, mined-land feature, road corridor, or historic place does not prove ownership, danger, causation, liability, access, compliance, or present condition.

## 6. Public safety and governed outcomes

| Request or output class | Bounded posture | Reason |
|---|---|---|
| Released, broad, time-labeled county context with resolving citations | `ANSWER` only when evidence, policy, review, and release conditions pass | Keeps the result within admitted public-safe evidence |
| Missing, stale, conflicting, overly coarse, or unresolvable evidence | `ABSTAIN` | Fluency cannot substitute for evidence, source role, scale, or currentness |
| Property-specific flood risk, emergency instruction, insurance advice, permit conclusion, or present-hazard routing | `ABSTAIN` or `DENY`, with the responsible official source identified when available | KFM is not an emergency, insurance, permitting, surveying, or engineering authority |
| Registered-access property data or exact living-person-linked parcel attributes | `DENY` | Prevents access-boundary bypass, privacy harm, and reconstruction |
| Parcel, appraisal, cadastral, or map geometry presented as ownership, legal boundary, survey, or title truth | `DENY` or `ABSTAIN` | Administrative context does not establish legal title or survey authority |
| Exact or reconstructive cemetery, burial, cultural-resource, sacred, archaeological, or protected-site detail | `DENY` | Prevents cultural, privacy, stewardship, and site-protection harm |
| Exact mine, bridge, road, utility, levee, work-zone, or other infrastructure vulnerability beyond an approved public source | `DENY` | Public context does not authorize harmful operational inference |
| Cross-source inference of causation, liability, compliance, access rights, water rights, engineering fitness, or present danger | `DENY` or `ABSTAIN`, as accepted policy requires | Separate contextual sources do not jointly prove the inferred claim |
| Resolver, policy, carrier, citation, or runtime failure | `ERROR` with no unsupported fallback claim | Failure must remain visible and fail closed |

Client-side hiding is not a sensitivity control. Protected detail must not be delivered to an ordinary public client, included in public logs or analytics, or reconstructed from tiles, filters, search, exports, caches, identifiers, or AI responses.

## 7. Evidence and readiness boundary

A Bourbon County public result must remain downstream of the governed KFM path:

1. identify a source once in the source-authority surface;
2. review authority, rights, access, time, geography, sensitivity, and correction behavior;
3. admit candidate material to `RAW`, or hold it in `WORK / QUARANTINE` when requirements are unresolved;
4. derive and validate `PROCESSED` material with transform and provenance lineage;
5. resolve every consequential `EvidenceRef` to an `EvidenceBundle` and apply policy;
6. make a separate promotion and release decision with correction and rollback targets;
7. serve only released public-safe artifacts through governed interfaces;
8. keep map rendering and AI interpretation subordinate to that evidence and decision state.

## 8. Smallest safe follow-up

The smallest legitimate follow-up is a **planning-evidence reconciliation**, not live ingestion:

1. review the build plan against current repository paths and remove only claims proven stale;
2. classify each proposed source by identity, authority, rights, access level, cadence, sensitivity, correction behavior, and permitted use;
3. choose one no-network synthetic county context or Focus payload fixture using current semantic and schema authorities rather than creating parallel object homes;
4. define expected negative outcomes for raw-service leakage, registered-access data, parcel-title claims, property-specific flood risk, exact cultural or burial locations, exact mine or infrastructure vulnerability, operational routing, and uncited generated claims;
5. prove source-role separation among administrative GIS, property records, flood regulation, observation and forecast, agriculture statistics, land cover, geology, transportation, and public history;
6. run the repository-native focused and aggregate checks, then record introduced versus inherited failures;
7. keep live source activation, release, deployment, and publication outside that packet.

This README does not authorize that follow-up; it states the dependency-closed boundary that a later implementation request must verify.
