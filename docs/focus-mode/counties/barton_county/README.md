# Barton County Focus Mode

> **Purpose.** Orient maintainers to the Barton County planning lane, make its
> wetlands, wildlife-geoprivacy, river, trail, agriculture, energy,
> property, infrastructure, and cultural-context boundaries visible, and route
> future work through KFM evidence, policy, review, release, correction, and
> rollback controls.

> [!IMPORTANT]
> **Tracked planning artifacts are not implementation or release evidence.**
> This directory contains this README and one Barton County build plan. Their
> presence prevents accidental duplicate planning; it does not establish source
> admission, semantic correctness, validator success, runtime behavior, release,
> deployment, or publication.

> [!CAUTION]
> **Placement remains unresolved.** This same-path update repairs an existing
> README under `docs/focus-mode/counties/barton_county/`. Accepted Directory
> Rules v2 treats Focus Mode as a composition scope; proposed ADR-0027 describes
> a different plural, kebab-case control plane but remains unaccepted. No file is
> moved, renamed, copied into a parallel tree, or declared the final canonical
> county write target here.

> [!WARNING]
> **The build plan combines public context with sensitive or high-consequence
> subjects.** Exact or reconstructive rare-species, nest, roost, wetland
> operations, private-well, farm-household, oil-and-gas infrastructure,
> cemetery, burial, cultural-resource, property, and water-rights detail must
> not reach an ordinary public client. Missing evidence, rights, safe
> resolution, policy, review, or release closure must produce a bounded
> `ABSTAIN`, `DENY`, or `ERROR` result rather than a fluent inference.

## 4. Proposed Barton County proof slice

The build plan proposes a public-safe county evidence cockpit centered on
Cheyenne Bottoms and Central Flyway context, Great Bend and the Arkansas River,
Santa Fe Trail and Walnut Creek interpretation, agriculture and wheat,
generalized oil-and-gas economic history, water and groundwater context, and
wetlands education and tourism. That is a **planning thesis**, not a verified
current product.

| Proposed element | Evidence needed before reliance | Non-effect of this README |
|---|---|---|
| County and community orientation | Registered authoritative geography source, vintage, geometry identity, rights, and released public-safe carrier | Does not declare a current boundary artifact or public layer |
| Wetlands and Central Flyway context | Distinct wetland, wildlife, observation, management, conservation, and interpretation source roles; valid time; rights; sensitivity; review | Does not establish a current ecological condition, migration event, or management status |
| Wildlife geoprivacy | Accepted sensitivity policy, public-safe transform, anti-reconstruction proof, domain review, and redaction lineage | Does not authorize exact species, nest, roost, or occurrence disclosure |
| Arkansas River, water, and groundwater context | Separate observation, modeled, regulatory, historical, and derived source roles; temporal scope; limitations; policy | Does not provide emergency, water-rights, engineering, irrigation, or property-specific advice |
| Santa Fe Trail, Walnut Creek, cemetery, and burial context | Authoritative historical support, route uncertainty, cultural review, public-safe geometry, rights, and correction path | Does not disclose exact protected locations or turn interpretive routing into surveyed fact |
| Agriculture, wheat, and land-cover context | Admitted aggregate source, measure definitions, vintage, transform receipt, and privacy review | Does not authorize farm-household, private-well, parcel, or title inference |

## 5. Public safety and governed outcomes

| Request or output class | Bounded posture | Reason |
|---|---|---|
| Released, broad, time-labeled county context with resolving citations | `ANSWER` only when evidence, policy, review, and release conditions pass | Keeps the result within admitted public-safe evidence |
| Missing, stale, conflicting, overly coarse, or unresolvable evidence | `ABSTAIN` | Fluency cannot substitute for evidence, source role, or currentness |
| Exact or reconstructive rare-species, nest, roost, occurrence, or sensitive habitat detail | `DENY` | Prevents ecological harm and defeats anti-reconstruction risk |
| Restricted wetland operations, control structures, water infrastructure, or management detail | `DENY` | Public context does not authorize operational or vulnerability exposure |
| Private well, farm household, parcel-owner, title, eligibility, water-rights, or property-specific result | `DENY` or `ABSTAIN`, as accepted policy requires | Prevents privacy, legal, and unsafe-reliance harm |
| Oil, gas, transport, water, or other infrastructure vulnerability analysis beyond approved public context | `DENY` | General economic or historical context does not authorize harmful operational inference |
| Exact cemetery, burial, sacred, archaeological, or protected trail-related location | `DENY` | Cultural sensitivity and site protection require fail-closed handling |
| Birding, tourism, marker, or generated narrative presented as scientific, regulatory, legal, or historical proof | `ABSTAIN` or `DENY` | Interpretation and generated language cannot replace an EvidenceBundle |
| Emergency alerting, present-hazard instruction, legal advice, or engineering recommendation | `ABSTAIN` and route to the responsible authority when available | KFM is not the emergency, legal, permitting, or engineering authority |
| Resolver, policy, carrier, citation, or runtime failure | `ERROR` with no unsupported fallback claim | Failure must remain visible and fail closed |

Client-side hiding is not a sensitivity control. Protected detail must not be
delivered to an ordinary public client, included in public logs or analytics,
or reconstructed from tiles, filters, search, exports, caches, identifiers, or
AI responses.

## 6. Evidence and readiness boundary

A Barton County public result must remain downstream of the governed KFM path:

1. identify a source once in the source-authority surface;
2. review authority, rights, access, time, geography, sensitivity, source role,
   and correction behavior;
3. admit candidate material to `RAW`, or hold it in `WORK / QUARANTINE` when
   requirements are unresolved;
4. derive and validate `PROCESSED` material with transform and provenance
   lineage;
5. resolve every consequential `EvidenceRef` to an `EvidenceBundle` and apply
   policy;
6. make a separate promotion and release decision with correction and rollback
   targets;
7. serve only released public-safe artifacts through governed interfaces;
8. keep map rendering and AI interpretation subordinate to that evidence and
   decision state.

## 7. Smallest safe follow-up

The smallest legitimate follow-up is a **planning-evidence reconciliation**, not
live ingestion:

1. review the build plan against current repository paths, current county
   inventory, and accepted Directory Rules, then remove only claims proven
   stale;
2. classify the first source candidates by authority, rights, cadence,
   sensitivity, source role, correction behavior, and allowed public use before
   any activation;
3. choose one no-network synthetic county-context fixture using current semantic
   and schema authorities rather than creating parallel object homes;
4. define exact negative outcomes for sensitive species, nests and roosts,
   wetland operations, private wells and farms, oil-and-gas vulnerability,
   cemetery and burial locations, tourism text as proof, water-rights claims,
   parcel/title claims, and uncited generated language;
5. run repository-native focused and aggregate checks, then record introduced
   versus inherited failures;
6. keep live source activation, public geometry, release, deployment, and
   publication outside that packet.

This README does not authorize that follow-up; it states the dependency-closed
boundary that a later implementation request must verify.
