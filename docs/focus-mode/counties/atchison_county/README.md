# Atchison County Focus Mode

> **Purpose.** Orient maintainers to the Atchison County planning lane, make its river, floodplain, property, infrastructure, and cultural-context boundaries visible, and route future work through KFM evidence, policy, review, release, correction, and rollback controls.

> [!IMPORTANT]
> **Tracked planning artifacts are not implementation or release evidence.** This directory contains this README and one Atchison County build plan. Their presence prevents accidental duplicate planning; it does not establish source admission, semantic correctness, validator success, runtime behavior, release, deployment, or publication.

> [!CAUTION]
> **Placement remains unresolved.** This same-path update repairs an existing README under `docs/focus-mode/counties/atchison_county/`. Accepted Directory Rules v2 treats Focus Mode as a composition scope; proposed ADR-0027 describes a different plural, kebab-case control plane but remains unaccepted. No file is moved, renamed, copied into a parallel tree, or declared the final canonical county write target here.

> [!WARNING]
> **The build plan combines public context with sensitive or high-consequence subjects.** Exact or reconstructive cultural-resource, cemetery or burial, private-parcel, living-person, utility, infrastructure-vulnerability, and property-specific flood-risk detail must not reach an ordinary public client. Missing evidence, rights, safe resolution, policy, review, or release closure must produce a bounded `ABSTAIN`, `DENY`, or `ERROR` result rather than a fluent inference.

The build plan proposes a public-safe county evidence cockpit centered on the relationship among the Missouri River edge, floodplain and named-creek context, agriculture, geology, transportation, and historical interpretation. That is a **planning thesis**, not a verified current product.

| Proposed element | Evidence needed before reliance | Non-effect of this README |
|---|---|---|
| County and municipal orientation | Registered authoritative geography source, vintage, geometry identity, rights, and released public-safe carrier | Does not declare a current boundary artifact or public layer |
| Missouri River, floodplain, and creek context | Separate regulatory, modeled, forecast, and observation source roles; valid time; limitations; policy and release evidence | Does not provide emergency advice, insurance guidance, or property-specific risk |
| Aggregate agriculture context | Admitted aggregate source, measure definitions, vintage, transform receipt, and anti-reidentification review | Does not authorize farm-specific inference |
| Geology and geohydrology context | Appropriate KGS or other admitted source role, scale, time, rights, and educational limitations | Does not provide engineering, foundation, slope, or hazard advice |
| Transportation and river-city history | Distinct current-infrastructure and historical source roles, stale-state handling, sensitivity review, and citations | Does not expose operational vulnerability or convert narrative into legal fact |

| Map and AI interpretation | Released public-safe carriers, resolvable EvidenceBundles, finite policy outcomes, governed runtime, correction and rollback support | Does not create a layer, route, model capability, or public answer |

The plan's recommended first milestone is a no-network, fixture-first river and flood-context shell. That milestone is still **PROPOSED**. No synthetic payload, live source, MapLibre layer, governed API route, policy decision, release manifest, or rollback rehearsal is created by this README.

## 5. Public safety and governed outcomes

| Request or output class | Bounded posture | Reason |
|---|---|---|
| Released, broad, time-labeled county context with resolving citations | `ANSWER` only when evidence, policy, review, and release conditions pass | Keeps the result within admitted public-safe evidence |
| Missing, stale, conflicting, overly coarse, or unresolvable evidence | `ABSTAIN` | Fluency cannot substitute for evidence, source role, or currentness |
| Property-specific flood risk, emergency instruction, insurance advice, or present-hazard routing | `ABSTAIN` or `DENY`, with the responsible official source identified when available | KFM is not an emergency, insurance, permitting, or engineering authority |
| Exact or reconstructive cemetery, burial, cultural-resource, private-parcel, living-person, utility, or protected-site detail | `DENY` | Prevents privacy, cultural, site-protection, and infrastructure harm |
| Bridge, rail, road, levee, utility, or drainage vulnerability analysis beyond an approved public source | `DENY` | Public context does not authorize harmful operational inference |
| Cross-source inference of legal boundary, title, causation, liability, compliance, or engineering fitness | `DENY` or `ABSTAIN`, as accepted policy requires | Separate contextual sources do not jointly prove the inferred claim |
| Resolver, policy, carrier, citation, or runtime failure | `ERROR` with no unsupported fallback claim | Failure must remain visible and fail closed |

Client-side hiding is not a sensitivity control. Protected detail must not be delivered to an ordinary public client, included in public logs or analytics, or reconstructed from tiles, filters, search, exports, caches, identifiers, or AI responses.

## 6. Evidence and readiness boundary

An Atchison County public result must remain downstream of the governed KFM path:

1. identify a source once in the source-authority surface;
2. review authority, rights, access, time, geography, sensitivity, and correction behavior;
3. admit candidate material to `RAW`, or hold it in `WORK / QUARANTINE` when requirements are unresolved;
4. derive and validate `PROCESSED` material with transform and provenance lineage;
5. resolve every consequential `EvidenceRef` to an `EvidenceBundle` and apply policy;
6. make a separate promotion and release decision with correction and rollback targets;
7. serve only released public-safe artifacts through governed interfaces;
8. keep map rendering and AI interpretation subordinate to that evidence and decision state.

1. review the build plan against current repository paths and remove only claims that are proven stale;
2. register or explicitly reject the first source candidates after rights, authority, cadence, sensitivity, and correction review;
3. choose one no-network synthetic `CountyFocusContext` or equivalent fixture using the current semantic and schema authorities rather than creating parallel object homes;
4. define expected negative outcomes for raw-service leakage, property-specific flood risk, exact cultural or cemetery locations, utility exposure, infrastructure vulnerability, and uncited generated claims;
