# Allen County Focus Mode

> **Purpose.** Orient maintainers to the Allen County planning lane, make its sensitive-context boundaries visible, and route future work through KFM evidence, policy, review, release, correction, and rollback controls.

> [!IMPORTANT]
> **Tracked planning artifacts are not implementation or release evidence.** This directory contains this README and one Allen County build plan. Their presence prevents accidental duplicate planning; it does not establish source admission, semantic correctness, validator success, runtime behavior, release, deployment, or publication.

> [!CAUTION]
> **Placement remains unresolved.** This same-path update repairs an existing README under `docs/focus-mode/counties/allen_county/`. Accepted Directory Rules v2 treats Focus Mode as a composition scope; proposed ADR-0027 describes a different plural, kebab-case control plane but remains unaccepted. No file is moved, renamed, copied into a parallel tree, or declared canonical here.

> [!WARNING]
> **The build plan's proposed environmental-remediation and public-health context is sensitive.** Exact or reconstructive residential, child-use, health, testing, cleanup, eligibility, property, or liability information must not reach a public client. Missing evidence, rights, safe resolution, policy, or review closure must produce a bounded `ABSTAIN`, `DENY`, or `ERROR` result rather than a fluent inference.

## 4. Proposed Allen County proof slice

The repository build plan proposes an Allen County slice centered on broad, source-attributed environmental-remediation context and a strong residential privacy and public-health boundary. It also proposes keeping hydrology, floodplain, geology, and agriculture context distinct so separate sources are not collapsed into unsupported contamination, exposure, property, compliance, or liability conclusions.

That is a **planning thesis**, not a verified current product. A legitimate implementation would need to prove each element independently:

| Proposed element | Evidence needed before reliance | Non-effect of this README |
|---|---|---|
| Broad municipal remediation context | Registered authoritative source, temporal scope, admitted evidence, rights, safe resolution, citations | Does not verify site facts or current status |
| Public-health explanation and official routing | Approved source role, currentness, health/privacy review, non-diagnostic language | Does not issue a health or safety judgment |
| Hydrology or flood context | Separate source identity, observation/model role, time basis, uncertainty, policy | Does not infer contamination, causation, parcel flood status, insurance, or permits |
| Geology and agriculture context | Appropriate source roles, scale, time, rights, limitations | Does not establish exposure, land condition, compliance, or liability |
| Map and AI interpretation | Released public-safe carriers, resolvable EvidenceBundles, finite policy outcomes, governed runtime | Does not create a layer, route, model capability, or public answer |

Do not copy source payloads, exact locations, or proposed machine objects into this directory to simulate completion. The county lane should point to governed objects in their owning roots once those objects exist and are reviewable.

## 5. Public safety and governed outcomes

| Request or output class | Bounded posture | Reason |
|---|---|---|
| Released, broad, time-labeled context with resolving citations | `ANSWER` only when evidence, policy, review, and release conditions pass | Keeps the response within admitted public-safe evidence |
| Missing, stale, conflicting, overly coarse, or unresolvable evidence | `ABSTAIN` | Fluency cannot substitute for evidence or currentness |
| Exact or reconstructive residence, child-use site, testing, cleanup, eligibility, health, property, or liability result | `DENY` | Prevents privacy harm, stigma, unsafe reliance, and unsupported individual inference |
| Cross-source inference of contamination, exposure, causation, compliance, insurance, or legal responsibility | `DENY` or `ABSTAIN`, as accepted policy requires | Separate contextual sources do not jointly prove the inferred claim |
| Resolver, policy, carrier, citation, or runtime failure | `ERROR` with no unsupported fallback claim | Failure must remain visible and fail closed |
| Emergency or present-hazard instruction | `ABSTAIN` and route to the responsible authority | KFM does not become the emergency authority |

Client-side hiding is not a sensitivity control. Protected detail must not be delivered to an ordinary public client, included in public logs or analytics, or reconstructed from tiles, filters, search, exports, caches, identifiers, or AI responses.

## 6. Evidence and readiness boundary

An Allen County public result must remain downstream of the governed KFM path:

1. identify a source once in the source authority surface;
2. review authority, rights, access, time, geography, sensitivity, and correction behavior;
3. admit candidate material to `RAW`, or hold it in `WORK / QUARANTINE` when requirements are unresolved;
4. derive and validate `PROCESSED` material with transform and provenance lineage;
5. resolve every consequential `EvidenceRef` to an `EvidenceBundle` and apply policy;
6. make a separate promotion and release decision with correction and rollback targets;
7. serve only released public-safe artifacts through governed interfaces;
8. keep map rendering and AI interpretation subordinate to that evidence and decision state.

### Readiness ledger

| Criterion | Current state | Closure required |
|---|---|---|
| Existing directory, README, and build-plan paths | `CONFIRMED` | Recheck on base drift or path change |
| Build-plan semantic accuracy and stale-metadata repair | `NOT_RUN` | Complete evidence-backed review and focused plan revision |
| Source identities, roles, terms, rights, access, cadence, and time coverage | `NOT_RUN` | Registry-backed source review |
| Public-safe geometry and anti-reconstruction boundary | `NOT_RUN` | Policy, domain review, transform lineage, and exact negative tests |
| EvidenceRef-to-EvidenceBundle resolution | `NOT_RUN` | Deterministic positive and missing/conflicting/revoked evidence proof |
| Contract, schema, policy, and validator agreement | `NOT_RUN` | Bind current accepted surfaces without creating parallel authority |
| Governed API, map, Evidence Drawer, and AI negative states | `NOT_RUN` | Synthetic no-network runtime and accessibility proof |
| Independent review, release manifest, correction, withdrawal, and rollback | `NOT_RUN` | Accountable decision evidence in the proper object families |
| Deployment and public parity | `UNKNOWN` | Separate authorized deployment and observation evidence after release |
