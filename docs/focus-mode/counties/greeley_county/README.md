## Source-role anti-collapse

A future Greeley slice must keep source roles explicit rather than combining every official or public page into one undifferentiated authority.

| Candidate source family implied by the plan | Permitted planning role | Must not be treated as |
|---|---|---|
| Census demographic, household, and business products | Vintage-specific aggregate statistical context and explicit unavailable or suppressed values | Person, household, employer, worker, current-population, government, property, or release authority |
| Agricultural census products | County-level, vintage-specific aggregate agriculture context with suppression retained | Farm, producer, worker, parcel, lease, facility, private-well, compliance, or current-condition evidence |
| County, Tribune, Horace, or other local-government authority | Current identity, jurisdiction, services, or notices within its verified remit | Census, agriculture, legal-time-zone, water-right, property-title, weather, or universal emergency authority |
| Federal legal-time authority | Legal time-zone rule, scope, effective date, and boundary within its remit | Local-government identity, ZIP-derived time, neighboring-county inference, or map-label confirmation |
| Historical transportation maps | Dated road-network and cartographic lineage | Current route, condition, access, ownership, closure, bridge safety, or emergency-travel authority |
| Current transportation service | Current road and travel information within its operating window | Historical, property, legal-access, emergency-management, or durable KFM truth |
| Weather and fire-weather authority | Current forecast, hazard, observation, and alert context within its remit | County narrative, long-lived answer, emergency-management replacement, or cross-domain authority |
| Groundwater, water-right, public-water, and flood authorities | Distinct observed, modeled, regulatory, allocation, service, or hazard roles | Interchangeable evidence, private-well condition, parcel entitlement, compliance, or engineering conclusion |

## Trust path and finite outcomes

A public Greeley County claim would need to follow the established KFM trust direction:

```text
source candidate
  -> RAW capture
  -> WORK / QUARANTINE review
  -> PROCESSED role-aware object
  -> EvidenceRef -> EvidenceBundle
  -> CATALOG / TRIPLETS projection
  -> privacy + policy + validation + review + release decision
  -> PUBLISHED public-safe artifact
  -> governed API
  -> Explorer presentation
```

The map, UI, county index, catalog, AI response, and this README are downstream or interpretive surfaces; none is sovereign truth.

| Outcome | Meaning |
|---|---|
| `ANSWER` | Evidence, privacy, policy, citation, time, precision, release, and consumer requirements all permit the bounded claim. |
| `ABSTAIN` | Evidence, freshness, authority, rights, jurisdiction, geometry, currentness, or release support is insufficient. |
| `DENY` | The request conflicts with small-population privacy, suppression, property, water-right, infrastructure, safety, rights, trust-membrane, or release controls. |
| `ERROR` | Required object shape, resolver, validator, policy evaluator, or governed service failed; do not degrade into an unsupported answer. |

`HOLD` remains a governance or workflow state rather than a public answer.
