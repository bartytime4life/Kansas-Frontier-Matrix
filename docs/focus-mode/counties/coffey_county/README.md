# Coffey County Focus Mode Documentation Boundary

> **Purpose.** This is the current human planning lane for a proposed Coffey
> County Focus Mode. It connects the sibling plan to KFM evidence, safety,
> sensitivity, release, correction, and rollback boundaries without claiming
> that the planned product exists.

> [!IMPORTANT]
> **Documentation is not a release.** Neither file in this directory admits a
> source, resolves an `EvidenceRef`, creates a governed payload, deploys a
> route, or publishes a county experience.

> [!CAUTION]
> **Path convergence remains on HOLD.** The singular, snake_case lane is current
> repository fact. Proposed ADR-0027 does not authorize a move, rename,
> deletion, or parallel plural tree.

## Authority and non-effects

This README may explain current files, distinguish repository fact from
proposal, and preserve safety boundaries. It does not establish:

- source authority, rights, retrieval, admission, freshness, or provenance;
- canonical hydrology, floodplain, transport, energy, agriculture, geology,
  ecology, land, title, property, or cultural-resource truth;
- current emergency, road, flood, reservoir-operation, facility, or visitor
  safety advice;
- parcel ownership, legal title, access, property risk, or regulation;
- critical-infrastructure vulnerability, security, operational, emergency-plan,
  or precision-targeting detail;
- contract or schema meaning, policy decisions, validator behavior, API or UI
  behavior, release, deployment, publication, correction, or rollback.

A map, card, test, workflow, pull request, merge, or generated narrative proves
only what that artifact directly demonstrates.

### Directory Rules basis

The target is an existing human-facing file under the `docs/` responsibility
root. The smallest reversible action is a same-path documentation update.
Accepted ADR-0029 makes `docs/doctrine/directory-rules.md` the writable
Directory Rules authority. Proposed ADR-0027 describes a possible county
control-plane convergence but does not authorize structural migration.

## Proposed proof slice

The plan proposes
`coffey-county-public-safe-source-and-fixture-slice`. A safe first packet is
source-ledger-, policy-, and fixture-first:

| Candidate context | Permitted purpose | Required boundary |
|---|---|---|
| County orientation | Broad place context | No ownership, access, hazard, or current-condition inference |
| River and reservoir | Hydrology and historical explanation | No live operations, flood, route, or safety instruction |
| Floodplain | Explain official hazard-source roles | Not a survey, permit, insurance, site determination, or alert |
| County GIS | Administrative and cartographic context | Parcel or tax geometry is not title, ownership, permission, or legal boundary |
| Agriculture | County aggregate | No farm, producer, household, parcel, yield, or management inference |
| Geology and land cover | Source-scoped interpretation | Preserve date, scale, method, uncertainty, and derivative status |
| Public energy context | Minimum public institutional context | No vulnerabilities, systems, routes, routines, plans, or precision overlays |
| Transportation | General route and project orientation | No routing guarantee, live closure, or safety conclusion |
| Ecology and recreation | Generalized public education | No sensitive exacts, encounter optimization, or current assurance |
| Cultural and archaeology context | Reviewed public interpretation | Exact site, burial, sacred, or protected location denied |

The first packet should prove refusal, abstention, safe generalization, and
evidence gaps before rich mapping.

<a id="safety-and-finite-outcomes"></a>

## Safety and finite outcomes

The reason codes below are **PROPOSED documentation vocabulary**, not active
policy.

| Request | Default outcome | Candidate reason code |
|---|---|---|
| Vulnerability or security-sensitive facility detail | `DENY` | `CRITICAL_INFRASTRUCTURE_DETAIL_DENIED` |
| Current flood, road, reservoir, facility, or visitor safety advice | `DENY` or `ABSTAIN`; refer to an appropriate current official source | `LIVE_EMERGENCY_GUIDANCE_OUT_OF_SCOPE` |
| GIS or parcel data treated as ownership or title | `ABSTAIN` or `DENY` | `PARCEL_IS_NOT_TITLE_TRUTH` |
| Site floodplain, permit, engineering, insurance, or legal conclusion | `ABSTAIN` | `FLOODPLAIN_DETERMINATION_OUT_OF_SCOPE` |
| Sensitive species, nesting, habitat, or encounter exacts | `DENY` or approved generalization | `SENSITIVE_ECOLOGY_GEOMETRY_WITHHELD` |
| Exact archaeology, burial, sacred, or protected cultural location | `DENY` | `CULTURAL_RESOURCE_LOCATION_WITHHELD` |
| Unsupported aggregate-to-person, farm, parcel, or operator inference | `ABSTAIN` or `DENY` | `AGGREGATE_TO_INDIVIDUAL_INFERENCE_DENIED` |
| Evidence unavailable, stale, unresolved, or outside scope | `ABSTAIN` | `EVIDENCE_CLOSURE_INCOMPLETE` |
| Policy, validator, resolver, or runtime fault | `ERROR` | `FOCUS_RUNTIME_FAILURE` |

A future governed response may return:

| Outcome | Minimum condition |
|---|---|
| `ANSWER` | Released public-safe evidence resolves, policy allows, temporal/spatial scope fits, and citations validate |
| `ABSTAIN` | Evidence is missing, stale, conflicting, unresolved, or insufficient for the requested scope |
| `DENY` | Rights, sensitivity, security, privacy, property, cultural, or harmful-precision policy blocks exposure |
| `ERROR` | A contract, schema, resolver, policy, validator, or runtime operation fails |

Negative outcomes must not leak the protected detail they are withholding.

<a id="source-role-anti-collapse"></a>

## Source-role anti-collapse

The plan lists candidate sources, but a URL or public page is not an admitted
KFM source. Distinct roles must remain visible:

| Role | May support | Must not be silently treated as |
|---|---|---|
| Local administrative or GIS source | County geometry, address, road, tax, or administrative context within its stated role | Legal title, permission, engineering survey, current emergency truth, or universal spatial authority |
| Observation source | A measured value at a stated time, place, method, and quality | Forecast, model, regulation, or county-wide condition without support |
| Forecast or advisory source | Time-bounded modeled or official advisory context | Observation, guarantee, or KFM alert authority |
| Regulatory or administrative source | Official status, program, permit, or jurisdictional context | Physical condition, legal advice, or universal source authority |
| Statistical aggregate | County-scale summary with method and vintage | Individual, farm, operator, household, or parcel fact |
| Interpretive map or derivative | Source-scoped interpretation with scale and method | Primary observation or legal boundary |
| Public institutional page | Minimum public context | Security assessment, vulnerability model, operational state, or internal plan |
| KFM derived layer, card, tile, or narrative | Governed downstream carrier after release | Sovereign truth or replacement for evidence |

Before any candidate becomes usable, verify identity, authority role, rights and
terms, access method, cadence, time semantics, spatial fitness, sensitivity,
integrity, correction behavior, and public-use obligations.

<a id="trust-path-and-lifecycle"></a>

## Trust path and lifecycle

A proposed Coffey County claim should follow the same governed path as other
KFM claims:

```text
source candidate
  -> source identity, role, rights, and sensitivity review
  -> RAW capture with intake evidence
  -> WORK or QUARANTINE
  -> validated and transformed PROCESSED object
  -> CATALOG / TRIPLET references and EvidenceBundle closure
  -> policy, review, proof, release, correction, and rollback records
  -> PUBLISHED public-safe artifact
  -> governed API
  -> MapLibre / Evidence Drawer / Focus Mode projection
```

Required rules:

1. Public clients do not read `RAW`, `WORK`, `QUARANTINE`, candidate, canonical,
   or internal stores as their normal path.
2. `EvidenceRef` resolves to `EvidenceBundle` before a consequential `ANSWER`.
3. A source, map, tile, schema, validator, receipt, pull request, or merge is not
   a promotion decision.
4. Sensitive geometry and attributes are generalized or withheld before public
   delivery, with the transform and reason recorded.
5. Correction, withdrawal, supersession, and rollback remain visible and
   auditable.
6. AI may interpret released evidence; it cannot create source, policy, review,
   or release authority.

## Smallest safe follow-up

The next implementation packet should remain no-network and non-publication:

1. reconcile the sibling plan's stale repository assumptions without changing
   source admission or product state;
2. define a bounded source-candidate ledger with distinct source roles, rights
   placeholders, sensitivity, cadence, and correction notes;
3. add deterministic synthetic fixtures for `ANSWER`, `ABSTAIN`, `DENY`, and
   `ERROR`, including critical-infrastructure, live-emergency, parcel/title,
   floodplain-fitness, ecology, and cultural-location failures;
4. bind the fixtures to verified contract and schema authority;
5. run no-network validators and negative tests;
6. keep release, deployment, publication, and live-source activation on hold.

That packet should be split if contract, schema, policy, and county-control-plane
authority cannot be closed coherently in one review unit.

## Maintenance and rollback

Review this README when:

- the sibling plan changes materially;
- source candidates are added, admitted, withdrawn, or superseded;
- an approved Coffey public-safe geometry or sensitivity profile changes;
- ADR-0027 changes status or a county-path migration is authorized;
- Focus contract, schema, policy, validator, API, or Explorer behavior changes;
- a Coffey release, correction, withdrawal, or rollback record is created;
- the county index no longer reflects the directory inventory.

Correction rules:

- correct unsupported prose through a focused reviewed change;
- preserve prior hashes and source lineage when a public or review decision
  depends on the earlier state;
- do not rewrite a historical receipt or release record to conceal an error;
- use a correction, supersession, withdrawal, or rollback object when the
  affected surface has crossed a governed lifecycle boundary.

Rollback before merge is closing the draft pull request. After an authorized
merge, rollback is a reviewed revert of the README and its generated authoring
receipt, followed by the same documentation and integrity checks. A repository
revert is not a release rollback if any public release later depends on these
bytes.
