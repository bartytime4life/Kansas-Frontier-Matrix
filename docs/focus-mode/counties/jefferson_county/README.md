# Jefferson County Focus Mode Documentation Boundary

> **Purpose.** Explain the Jefferson County planning lane now present in the
> repository and the evidence, safety, sensitivity, review, correction, and
> rollback conditions that must remain visible before any county Focus Mode can
> become more than a proposal.

> [!IMPORTANT]
> **This directory contains documentation, not a released county product.**
> The sibling plan and this README do not admit a source, create an
> `EvidenceBundle`, activate policy, implement a governed API route, approve a
> map or generated answer, or create release or publication state.

> [!CAUTION]
> **Placement remains on compatibility HOLD.** This README stays at the tracked
> singular, snake_case path. Accepted Directory Rules v2 supports same-path
> documentation under `docs/`; proposed ADR-0027 cannot authorize a migration
> to a plural, kebab-case control plane. Do not create a second writable
> Jefferson lane by inference.

> [!WARNING]
> **Managed-water and flood context can create unsafe confidence.** The sibling
> plan proposes a Perry Lake and Delaware River proof slice. KFM must not turn
> dated planning material, maps, observations, or generated language into
> current reservoir operations, flood or recreation safety, property, permit,
> insurance, engineering, environmental-health, or emergency guidance.

## 5. Public safety, sensitivity, and finite outcomes

### Fail-closed matrix

| Request or display class | Bounded posture | Reason |
|---|---|---|
| Released, time-labeled Jefferson context with resolving evidence and explicit limitations | `ANSWER` | Evidence, source role, policy, limits, and release state are visible |
| Missing, stale, conflicting, corrected, superseded, revoked, or rights-unclear evidence | `ABSTAIN` | The claim is not supportable |
| Current boating, camping, crossing, reservoir, release, closure, or flood-safety advice | `DENY` and route to the responsible current authority | KFM is not an operational or emergency service |
| Dam, outlet, protection-system, or vulnerability detail beyond public educational need | `DENY` or exclude | Operational and infrastructure risk |
| Parcel-specific flood, permit, insurance, title, engineering, or safe-property conclusion | `DENY` | Property and regulatory authority remain external |
| Exact sensitive habitat, wildlife concentration, archaeology, burial, cemetery, or culturally sensitive location | `DENY` | Harmful precision and misuse risk |
| Aggregate agriculture joined to a farm, family, person, owner, lease, or parcel | `DENY` | Privacy, property, and statistical misuse |
| Historical or program context presented as current health, compliance, water-quality, or individual responsibility | `ABSTAIN` or `DENY` | Source-role and time-basis collapse |
| Direct public access to `RAW`, `WORK`, `QUARANTINE`, candidate geometry, or model output | `ERROR` or `DENY` | Trust-membrane bypass |
| Runtime, schema, evidence, or policy failure | `ERROR` | A bounded fault must stay visible without leaking protected detail |

A harmless-looking field can become sensitive when joined with historic
overlays, parcels, infrastructure, wildlife, agriculture, or current
observations. Future validation must test individual layers and combined query
contexts. Redaction in one carrier is insufficient when another reconstructs
the denied fact.

A public interface must visibly distinguish `ANSWER`, `ABSTAIN`, `DENY`, and
`ERROR`, including missing, stale, conflicting, corrected, superseded,
restricted, or revoked evidence and generalized or withheld geometry.

## 6. Source role, rights, and currentness

The plan names source families reviewed during its 2026-05-22 authoring run.
This README neither refreshes those checks nor admits a source.

| Plan-named source family | Proposed role | Must not become |
|---|---|---|
| Jefferson County public surfaces | Administrative, floodplain-routing, and public-history context | Complete cultural authority, parcel judgment, current emergency instruction, or title evidence |
| U.S. Army Corps of Engineers Perry material | Federal project and public reservoir context | KFM operational guidance, engineering assessment, current release state, or vulnerability analysis |
| FEMA and Kansas flood-information surfaces | Official flood-hazard source routing and effective-map context | KFM parcel verdict, insurance or permit decision, or safety guarantee |
| Kansas Water Office program material | State water-planning and watershed-program context | Current water-quality diagnosis, individual eligibility, blame, or compliance finding |
| Kansas wildlife and park material | Public recreation and ecology context | Current-access guarantee or unrestricted sensitive-location detail |
| Kansas agriculture statistics | County statistical aggregate | Farm, owner, family, parcel, productivity, responsibility, or compliance truth |
| Kansas Geological Survey material | Scientific and historical geologic context | Site engineering, water-supply, contamination, or health conclusion |
| U.S. Geological Survey observation surface | Potential dated observation source | Alert, forecast, official instruction, or direct raw public feed |

Before a source supports a consequential public claim, review and record:

1. stable identity, publisher, authority role, and exact version or retrieval state;
2. publication, effective, observation, and retrieval times as distinct fields;
3. rights for citation, extraction, transformation, redistribution, and display;
4. allowed claim scope and prohibited inference;
5. sensitivity, minimum necessary detail, safe resolution, and reconstruction risk;
6. freshness, outage, correction, revision, supersession, and withdrawal behavior;
7. deterministic provenance through any public-safe derivative;
8. an `EvidenceRef` resolving to an admissible `EvidenceBundle`;
9. policy, accountable review, release, correction, and rollback references.

The plan records an apparent agricultural year-label ambiguity. It remains
`NEEDS VERIFICATION`; future work must resolve the authoritative period rather
than repeat a convenient label.

Public access is not permission to extract, join, tile, redistribute, or
publish. Official-source status also does not make every field necessary or
safe for a KFM derivative.

## 7. Evidence and readiness boundary

A public Jefferson result remains downstream of the governed KFM path:

1. identify a source once in its appropriate authority surface;
2. review authority, rights, time, geography, sensitivity, correction, and
   minimum-necessary use;
3. admit candidate material to `RAW`, or hold it in `WORK / QUARANTINE`;
4. derive and validate `PROCESSED` material with transform and provenance lineage;
5. create catalog or triplet relationships without treating indexes as truth;
6. resolve each consequential `EvidenceRef` to an `EvidenceBundle` and apply policy;
7. make a separate promotion and release decision with correction, withdrawal,
   and rollback targets;
8. serve only released public-safe artifacts through governed interfaces;
9. keep maps and generated interpretation subordinate to evidence and decision state.

## 9. Validation, maintenance, and rollback

### Documentation checks

This slice should verify:

- one bounded metadata block and one H1;
- ordered headings, balanced comments and fences, consistent tables, LF line
  endings, and a final newline;
- all same-document fragments and repository-relative links;
- metadata conformance, including a single bounded `type` token;
- final-byte SHA-256 and Git blob identity;
- generated-receipt schema and artifact-hash parity;
- absence of credentials, private endpoints, coordinates, personal records,
  exact protected locations, live operational payloads, and unsupported
  current-state claims;
- exact branch comparison, changed paths, remote bytes, and draft-PR state.

Repository-native full validation and hosted exact-head checks remain separate
evidence. A pending, inherited, unrelated, or unavailable failure must be
classified rather than silently waived.

### Review questions

- Does the README keep the sibling plan proposed and time-bounded?
- Do reservoir, flood, recreation, property, permit, insurance, engineering,
  environmental-health, and emergency boundaries prevent operational authority?
- Do ecology, wildlife, archaeology, burial, cultural, infrastructure,
  agriculture, and landowner boundaries fail closed without leaking detail?
- Do `ANSWER`, `ABSTAIN`, `DENY`, and `ERROR` remain finite outcomes?
- Is the singular/plural placement HOLD still visible?
- Are source admission, rights, specialist review, policy, correction,
  release, deployment, and publication clearly separate?

### Update triggers

Re-review this file when:

- the Jefferson directory, sibling plan, county index, parent Focus docs, or
  county template changes;
- ADR-0027, ADR-0029, or accepted Directory Rules authority changes;
- a Jefferson source is admitted, corrected, superseded, revoked, or rejected;
- reservoir, flood, property, recreation, ecology, culture, archaeology,
  agriculture, science, or harmful-precision posture changes;
- a county contract, schema, policy profile, validator, fixture, governed API,
  renderer, Evidence Drawer, or generated adapter becomes reviewable;
- a promotion, release, correction, withdrawal, or rollback object is proposed.

### Rollback and correction

Before merge, close or abandon the draft pull request and leave `main`
unchanged. After an authorized merge, revert this README and its generated
authoring receipt together, or apply a bounded forward correction against the
actual merged bytes. Do not rewrite shared history.

A documentation rollback would not reverse source admission, policy, runtime,
release, deployment, or publication because none is created here. A later
public Jefferson artifact would require its own correction, withdrawal, cache
invalidation, supersession, and rollback controls.
