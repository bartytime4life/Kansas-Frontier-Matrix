## Anderson County planning posture

The plan's durable design question is:

> Can a county-scale map help a user understand official local-source roles and broad place context while refusing legal reliance, individualized inference, live safety claims, operational exposure, and harmful precision?

That question is suitable for further review. The proposed answer is not yet implementation evidence.

### Candidate planning themes

| Theme carried by the plan | Source role required before use | Allowed planning direction | Fail-closed boundary |
|---|---|---|---|
| County administrative context | Admitted county-government source with currentness and rights metadata | Explain public service categories and link to official authority. | No title, ownership, access, legal, emergency, or living-person inference. |
| Garnett municipal context | Admitted city-government source | Explain municipal source categories and official contact paths. | No zoning, code, utility, court, or compliance determination. |
| Working-landscape aggregates | Admitted statistical or land-cover source | County-level aggregate context with time and unit shown. | No farm, household, owner, parcel, health, or private-well profile. |
| Recreation and trail context | Admitted official facility/recreation source | Reviewed public orientation and dated notices. | No live closure, access, water, hunting, or safety advice without current official evidence. |
| Transportation context | Admitted transportation source and reviewed public-safe transform | Generalized orientation and historical context. | No operational, vulnerability, response, or restricted infrastructure detail. |
| Historical context | Admitted historical source with rights and sensitivity review | Bounded orientation with citations and limitations. | No unsupported interpretation or archaeology, burial, sacred, or reconstructive precision. |
| Water, flood, and hazard context | Admitted scientific or regulatory source with temporal scope | Generalized, dated context. | No legal flood determination, insurance advice, emergency direction, water-right, potability, or property-level conclusion. |

Source names in the sibling plan are research leads. Public availability does not prove authority, rights, fitness, freshness, or derivative-display permission.

## Trust membrane and finite outcomes

Every consequential public claim must stay subordinate to evidence and policy:

1. establish the county, map, time, layer, and audience scope;
2. retrieve only through governed interfaces or released public-safe artifacts;
3. resolve each `EvidenceRef` to an admissible `EvidenceBundle`;
4. apply rights, sensitivity, policy, currentness, and review checks;
5. return a finite envelope with citations, limitations, and correction context;
6. refuse or narrow the response when those dependencies do not close.

| Outcome | Use in an eventual Anderson County surface | Required discipline |
|---|---|---|
| `ANSWER` | Evidence supports a bounded, public-safe, time-scoped response. | Cite the resolved evidence and expose limitations. |
| `ABSTAIN` | Evidence is missing, stale, unresolved, conflicted, or unfit for the requested precision. | State the gap and, when safe, identify the official source class needed. |
| `DENY` | Policy or sensitivity forbids the request or precision. | Do not leak protected content through explanation, map state, logs, or alternatives. |
| `ERROR` | A contract, resolver, validator, renderer, or dependency failed. | Preserve failure context without converting failure into an unsupported answer. |

EvidenceBundle outranks generated language. A map, tile, graph, search index, summary, badge, screenshot, test, or model response is a delivery or interpretive surface, not sovereign truth.

## Rights, sensitivity, and currentness

| Risk class | Default posture | Evidence required to narrow the default |
|---|---|---|
| Property title, ownership, access, zoning, codes, compliance, or legal reliance | `DENY` or `ABSTAIN`; redirect to current official authority. | Admissible authority, temporal scope, policy approval, and a product contract that expressly permits the claim. |
| Living-person, household, farm, parcel, private-well, health, or genomic inference | `DENY`. | A separately governed use case with consent, rights, sensitivity, and policy closure; none is established here. |
| Emergency, law-enforcement, facility, road, trail, or public-safety status | `ABSTAIN` or `DENY`; never treat a planning document as a live feed. | Current official notice admitted through a bounded connector and governed response path. |
| Archaeology, burial, sacred place, rare species, vulnerable infrastructure, or harmful precision | `DENY` exact or reconstructive detail; use reviewed generalization only. | Documented sensitivity review, transformation receipt, policy decision, and release approval. |
| Rights and redistribution | `HOLD` until verified. | Source terms, license or permission, attribution, derivative-display scope, retention, and correction duties. |
| Source freshness | `ABSTAIN` when the observation, effective, retrieval, release, correction, or supersession time is missing or unfit. | Explicit temporal roles and a source-specific stale threshold. |

Client-side hiding is not a sensitivity control. Protected or unreleased bytes must not be delivered to a public client.

## Safe authoring and maintenance

### Review sequence

1. Pin the county directory, index row, sibling plan, governing doctrine, and open overlapping work.
2. Classify each plan claim as current repository fact, historical planning lineage, proposal, unknown, or verification item.
3. Resolve scope identity and accountable ownership before introducing machine or lifecycle state.
4. Admit sources once under their owning registry and lifecycle lanes; reference them from the county scope.
5. Reuse accepted shared contracts, schemas, policy, fixtures, validators, and release families; do not create county-local duplicates by default.
6. Add deterministic positive and negative fixtures using synthetic, rights-safe data.
7. Prove `ANSWER`, `ABSTAIN`, `DENY`, and `ERROR` behavior through governed boundaries before public-facing claims.
8. Require evidence, rights, sensitivity, review, release, correction, and rollback closure before any publication transition.

### Filename drift

The `_FIXED` suffix is repository evidence, not a quality or canonicality guarantee. This README intentionally does not rename the plan because a sound rename requires:

- exact inbound-reference and consumer inventory;
- a selected canonical filename and compatibility posture;
- index and validator reconciliation;
- preserved Git history and link repair;
- a reversible migration plan;
- confirmation that no concurrent branch owns the same bytes.

Until that slice is authorized and verified, link to the tracked filename exactly and keep `PLAN_NAME_DRIFT` visible.

### Review triggers

Re-review this page when the plan bytes or name change; the county index changes grammar; ADR-0027 changes status; the Focus path receives an accepted alias or migration; a scope identity is registered; sources, contracts, schemas, policy, fixtures, or validators are admitted; a governed runtime consumes Anderson County; or any release, correction, rollback, deployment, or publication claim appears.
