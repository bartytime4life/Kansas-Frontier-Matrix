# Dickinson County Focus Mode

> **Purpose.** Orient maintainers to the Dickinson County planning lane, make
> its evidence and sensitive-context boundaries visible, and route future work
> through KFM source, evidence, policy, review, release, correction, and rollback
> controls.

> [!IMPORTANT]
> **Tracked planning artifacts are not implementation or release evidence.**
> This directory contains this README and one Dickinson County build plan. Their
> presence prevents accidental duplicate planning; it does not establish source
> admission, semantic correctness, validator success, runtime behavior, release,
> deployment, or publication.

> [!CAUTION]
> **Placement remains a compatibility question.** This same-path update repairs
> an existing README under `docs/focus-mode/counties/dickinson_county/`.
> Accepted Directory Rules v2 governs placement; proposed ADR-0027 describes a
> plural, kebab-case control plane but remains unaccepted. No file is moved,
> renamed, copied into a parallel tree, or declared canonical here.

> [!WARNING]
> **The plan combines public GIS, floodplain and stream context, transport
> projects, agriculture, geology, and heritage with sensitive detail.** Exact or
> reconstructive parcel-owner, cemetery or burial, archaeology or sacred-site,
> living-person, ecological occurrence, emergency, NG911, or infrastructure
> vulnerability detail must not reach an ordinary public client. Missing
> evidence, rights, safe resolution, policy, or review closure must produce a
> bounded `ABSTAIN`, `DENY`, or `ERROR`, not a fluent inference.

## 4. Proposed Dickinson County proof slice

The build plan proposes a public-safe county evidence cockpit centered on the
Smoky Hill River and Lower Smoky Hill floodplain context, the Flint Hills to
Smoky Hills geologic transition, county-scale agriculture, dated I-70 and K-15
transportation change, Abilene, and Eisenhower public heritage. It also treats
the county's broad public-GIS availability as a governance test: discoverable
data is not automatically admitted, safe, authoritative for every claim, or fit
for public redistribution.

That is a **planning thesis**, not a verified current product.

| Proposed element | Evidence needed before reliance | Non-effect of this README |
|---|---|---|
| County, community, and map orientation | Registered authoritative geography source, vintage, geometry identity, rights, and released public-safe carrier | Does not declare a current boundary artifact or public layer |
| Smoky Hill River, stream, and floodplain context | Separate regulatory, observation, forecast, historical, and derived source roles; valid time; limitations; policy; release state | Does not provide an emergency warning, flood determination, insurance, permitting, or property-specific conclusion |
| Flint Hills-to-Smoky Hills geology and sand-hill context | Admitted geologic source, scale, interpretation limits, rights, and review | Does not establish groundwater availability, engineering fitness, mineral rights, or parcel suitability |
| Agriculture at county scale | Admitted aggregate source, definitions, vintage, transform lineage, privacy review, and citations | Does not authorize farm-household, operator, parcel, production, private-well, or title inference |
| I-70 and K-15 project context | Dated authoritative project records, temporal semantics, supersession behavior, limitations, and public-safe geometry | Does not report current traffic, closure, detour, bridge safety, or travel conditions |
| Abilene and Eisenhower public heritage | Authoritative institutional or historical sources, rights, scope, citations, and correction path | Does not turn interpretation into broad biographical or historical proof |
| County GIS discovery surface | Source-by-source authority, rights, access, retention, sensitivity, allowed-use, and correction review | Does not admit feature services, parcel data, cemetery records, survey references, burn restrictions, or NG911 material |
| Map and AI interpretation | Released public-safe carriers, resolvable EvidenceBundles, finite policy outcomes, governed runtime, correction, and rollback support | Does not create a layer, route, model capability, or public answer |

Do not copy source payloads, sensitive locations, or proposed machine objects
into this directory to simulate completion. The county lane should reference
governed objects in their owning roots only after those objects exist and are
reviewable.

## 5. Public safety and governed outcomes

| Request or output class | Bounded posture | Reason |
|---|---|---|
| Released, broad, time-labeled county context with resolving citations | `ANSWER` only when evidence, policy, review, and release conditions pass | Keeps the result within admitted public-safe evidence |
| Missing, stale, conflicting, overly coarse, or unresolvable evidence | `ABSTAIN` | Fluency cannot substitute for evidence, source role, or currentness |
| Parcel-owner, individual tax, title, private-access, property-value, eligibility, liability, or other person/property-specific inference | `DENY` or `ABSTAIN`, as accepted policy requires | Public records do not automatically authorize aggregation, inference, or unsafe reliance |
| Exact or reconstructive cemetery, grave, burial, sacred, archaeological, or protected cultural location | `DENY` | Cultural sensitivity and site protection require fail-closed handling |
| Exact ecological occurrence, nest, roost, den, sensitive habitat, or other harmful-precision detail | `DENY` or reviewed generalization | Prevents harm and reconstruction through map, search, export, cache, or AI surfaces |
| Burn permission, current restriction interpretation, emergency flood guidance, evacuation, or incident intelligence | `ABSTAIN` and route to the responsible live authority | Focus Mode is not the emergency or incident authority |
| Current road condition, closure, detour, bridge safety, or travel instruction | `ABSTAIN` and route to the responsible transportation authority | Dated project context is not live travel authority |
| NG911, response-district, address, utility, water, transport, or other infrastructure vulnerability detail | `DENY` | Public context does not authorize harmful operational inference |
| Cross-source inference of causation, water availability, regulatory status, engineering fitness, ownership, or legal responsibility | `DENY` or `ABSTAIN` | Separate contextual sources do not jointly prove the inferred claim |
| Resolver, policy, carrier, citation, or runtime failure | `ERROR` with no unsupported fallback claim | Failure must remain visible and fail closed |

Client-side hiding is not a sensitivity control. Protected detail must not be
delivered to an ordinary public client, included in public logs or analytics,
or reconstructed from tiles, filters, search, exports, caches, identifiers, or
AI responses.

## 6. Evidence and readiness boundary

A Dickinson County public result must remain downstream of the governed KFM
path:

1. identify a source once in the source-authority surface;
2. review authority, rights, access, time, geography, sensitivity, source role,
   and correction behavior;
3. admit candidate material to `RAW`, or hold it in `WORK / QUARANTINE` when
   requirements are unresolved;
4. derive and validate `PROCESSED` material with transform and provenance
   lineage;
5. resolve every consequential `EvidenceRef` to an `EvidenceBundle` and apply
   policy;
6. make a separate promotion and release decision with correction and rollback
   targets;
7. serve only released public-safe artifacts through governed interfaces;
8. keep map rendering and AI interpretation subordinate to that evidence and
   decision state.

## 7. Smallest safe follow-up

The smallest legitimate follow-up is a **planning-evidence reconciliation**, not
live ingestion:

1. review the build plan against current repository paths, current county
   inventory, and accepted Directory Rules, then remove only claims proven
   stale;
2. classify the first county GIS, hydrology, floodplain, geology, agriculture,
   transportation, and public-history candidates by authority, rights, cadence,
   sensitivity, source role, correction behavior, and allowed public use before
   any activation;
3. choose one no-network synthetic county-context fixture using current semantic
   and schema authorities rather than creating parallel object homes;
4. define exact negative outcomes for parcel ownership, graves and burials,
   archaeology and sacred sites, ecological occurrences, burn restrictions,
   emergency guidance, live travel claims, NG911 and infrastructure detail,
   water or flood determinations, title claims, and uncited generated language;
5. run repository-native focused and aggregate checks, then record introduced
   versus inherited failures;
6. keep live source activation, public geometry, release, deployment, and
   publication outside that packet.

This README does not authorize that follow-up; it states the dependency-closed
boundary that a later implementation request must verify.
