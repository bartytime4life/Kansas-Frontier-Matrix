# Cloud County Focus Mode

> **Purpose.** Orient maintainers to the Cloud County planning lane, make its managed-wetland, Republican River, water-administration, agriculture, geology, transportation, built-heritage, property, currentness, and sensitive-location boundaries visible, and route future work through KFM evidence, policy, review, release, correction, and rollback controls.

> [!IMPORTANT]
> **Tracked planning artifacts are not implementation or release evidence.** This directory contains this README and one Cloud County build plan. Their presence prevents accidental duplicate planning; it does not establish source admission, semantic correctness, validator success, runtime behavior, release, deployment, or publication.

> [!CAUTION]
> **Placement remains unresolved.** This same-path update modernizes the existing README under `docs/focus-mode/counties/cloud_county/`. Accepted Directory Rules v2 treats Focus Mode as a composition scope; proposed ADR-0027 describes a different plural, kebab-case control plane but remains unaccepted. No file is moved, renamed, copied into a parallel tree, or declared the final canonical county write target here.

> [!WARNING]
> **Public landscape interpretation must not become harmful precision, current operational advice, or a legal determination.** Cloud County context cannot support exact sensitive wildlife or management detail, current refuge/access/hunting guidance, personal water-right or compliance conclusions, private parcel/person/tax/title exposure, archaeological or sacred-site precision, infrastructure-vulnerability analysis, current road-status claims, or present-condition conclusions from historical scientific sources without appropriately scoped evidence and authority. Missing evidence, currentness, rights, safe resolution, policy, review, or release closure must produce a bounded `ABSTAIN`, `DENY`, or `ERROR` result rather than a fluent inference.

## 5. Source-role and cross-domain boundaries

The build plan names source families that answer materially different questions. They must not be merged into one undifferentiated Cloud County truth layer.

| Planned source or object class | Legitimate bounded role | Must not be treated as |
|---|---|---|
| Wildlife-area management and public-rule material | Reviewed, dated public management, landscape, and rule context | Complete ecology, exact sensitive occurrence, current access/hunting advice, or unrestricted management detail |
| Hydrologic monitoring observation | Time-bound measurement or monitoring-location context with units, status, revision, and source identity | Alert, emergency advice, water-administration decision, legal conclusion, or parcel-specific risk |
| Water-administration material | Official administrative or regulatory explanation within its stated jurisdiction and effective period | Personal legal advice, compliance decision, or ownership of a person's water right |
| State or federal agricultural aggregate | Dated county-level statistical context | Individual farm, producer, landowner, operation, parcel, or household truth |
| Geological survey or historical scientific material | Educational geologic and groundwater-history context within stated scope | Current water quality, well condition, mineral rights, engineering suitability, or parcel hazard |
| County GIS, appraisal, parcel, or tax portal | Candidate administrative/reference source after terms, field, privacy, and title review | Automatic reuse permission, title truth, living-person exposure, or evidence closure |
| Current transportation authority | Present service or network context after source, cadence, rights, and release review | Historic interpretation, unrestricted infrastructure detail, or emergency authority beyond its role |
| Public historic-resource inventory or interpretation | Reviewed reference to expressly public and suitable built resources | Automatic designation, archaeology survey, burial or sacred-place disclosure, or undisclosed-location inference |
| Generated narrative | Evidence-bounded explanation after retrieval, policy, and citation checks | Source truth, rights decision, sensitivity authority, release approval, or proof |

Cross-domain interpretation must preserve the owning lane for each supported claim. A county composition may relate habitat, fauna, flora, agriculture, hydrology, geology, hazards, transportation, settlements/infrastructure, and archaeology/heritage only through governed references. It does not transfer ownership to the county folder.

## 6. Public-safety and governed outcomes

### Finite outward behavior

| Outcome | Cloud County use | Minimum public behavior |
|---|---|---|
| `ANSWER` | Released, in-scope evidence resolves and policy allows the requested public-safe claim | Show bounded wording, citations, source role, time basis, limitations, release state, and correction route |
| `ABSTAIN` | Evidence is missing, stale, unresolved, unsupported for the requested scale/time, or the question asks for an operational or property determination KFM does not own | State the evidence gap or scope limit; route to the responsible current authority where appropriate |
| `DENY` | Rights, sensitivity, sovereignty, harmful precision, private-person/property, legal, infrastructure, or unreleased-state rules block disclosure | Withhold or use an approved generalized public explanation without exposing control-defeating details |
| `ERROR` | Contract, schema, resolver, policy, citation, release, or runtime processing fails | Fail closed; expose a safe reason code and correction route, not internal paths or protected context |

### County-specific fail-closed matrix

| Request or failure | Required posture | Why |
|---|---|---|
| Exact rare, vulnerable, nesting, roosting, congregation, refuge-management, or other sensitive occurrence | `DENY` or separately reviewed coarse generalization | Ecological harm, geoprivacy, and operational sensitivity |
| Inferred sensitive occurrence from habitat, terrain, observations, absence, or model output | `DENY` | Derived likelihood must not reconstruct protected locations |
| “Is the refuge open now?”, “Where should I enter?”, or current hunting/access advice from a dated or unreleased source | `ABSTAIN` and route to the current official authority | KFM is not a current access, navigation, hunting, or operational-status system |
| USGS observation or MDS context used to decide personal pumping, water rights, or compliance | `DENY` | Observation, administration, and legal authority are distinct |
| Parcel ownership, tax, address, title, living-person detail, private route, or farm-level inference | `DENY` or omit | County context is not title truth and does not need private-person exposure |
| Archaeological, burial, sacred, ceremonial, collection, or undisclosed historic location | `DENY` absent qualified authority and a reviewed safe transform | Sovereignty, cultural sensitivity, and looting risk |
| Historical geology or groundwater material used for a present water-safety, property, well, or engineering claim | `ABSTAIN` or `ERROR` | Historical evidence cannot silently become current operational truth |
| Exact infrastructure vulnerability or non-public transportation, bridge, utility, or water-system weakness | `DENY` or reviewed generalization | Security and resilience sensitivity |
| Missing EvidenceBundle, policy decision, review, release, correction, or rollback closure | `ABSTAIN`, `DENY`, or `ERROR` according to the failed gate | A fluent explanation cannot replace trust closure |
| Public client reaches RAW, WORK, QUARANTINE, unpublished candidate, canonical store, ungoverned source, or direct model output | `DENY` and security correction | Trust-membrane violation |

Safe public reduction is a governed transform, not a style trick. Generalization, redaction, aggregation, suppression, or delay must occur before the public carrier is built and must retain a reason, transform identity, policy/review reference, and correction lineage appropriate to the risk. Client-side hiding alone is not a control.

## 8. Smallest safe follow-up

The smallest dependency-closed next slice is a **Cloud build-plan reconciliation**, not a live source connector or public map.

That follow-up should:

1. read the complete current build plan and then-current repository authority surfaces;
2. replace obsolete no-repository and uncertain-file-presence statements with pinned evidence;
3. classify every proposed path against accepted Directory Rules and visible ADRs without moving files;
4. convert dated 2026-05-22 source facts into a clearly bounded verification backlog unless each fact is independently rechecked;
5. map every proposed wetland, river, water-administration, agriculture, geology, transportation, heritage, property, map, and AI claim to an existing source, evidence, contract, schema, policy, fixture, validator, release, correction, and rollback dependency or mark the dependency `UNKNOWN`;
6. define a no-network negative-fixture matrix for exact ecology, inferred sensitive occurrence, stale operational status, USGS-to-MDS source-role collapse, legal inference, parcel/title/person exposure, cultural precision, historical-to-current mismatch, infrastructure vulnerability, missing evidence/release/rollback, and internal-store or direct-model bypass;
7. stop at documentation and synthetic design unless a separately authorized, dependency-closed implementation packet exists.

The proposed first proof remains **M-Cloud-01 — Wetland / Republican River Trust-Membrane Proof, Offline Only**, but it cannot advance from planning merely because the README or plan is complete. The first implementation packet should be selected only after authority, contract/schema ownership, source rights, sensitivity review, and negative-test homes are verified.

### Follow-up acceptance conditions

- the current plan path and tracked filename remain unambiguous;
- no parallel Focus documentation, schema, policy, source, evidence, proof, release, or publication home is created;
- source roles, dates, rights, sensitivity, precision, and non-goals are explicit;
- harmful requests have deterministic expected outcomes and safe reason families;

### Validation expectations for this README

A documentation change should verify, at minimum:

- one H1 and one stable `top` anchor;
- unique explicit section anchors and resolving local navigation;
- balanced code fences and structurally consistent Markdown tables;
- resolving repository-relative links against a pinned commit;
- UTF-8, LF endings, final newline, no tabs, and no trailing whitespace;
- no secret, protected payload, exact sensitive location, living-person/private-property detail, live operational access detail, or control-defeating transform parameter;
- a one-path diff unless a direct dependency is separately proven necessary;
- clear separation among documentation, validation, policy, release, deployment, and publication state.

### Correction and rollback

Before merge, close the draft pull request and abandon its feature branch. After an authorized merge, use a transparent revert or a bounded forward correction against then-current bytes. Do not rewrite shared history, restore unsupported claims as current fact, create a competing Cloud County lane, or delete historical planning lineage merely because it is stale.

A future correction to public Cloud County content must propagate through the authoritative evidence, policy, release, catalog, API, map, cache, export, search, generated-language, and notice surfaces that actually consumed the affected object. This README records that obligation; it does not prove the propagation system exists.
