> **Purpose.** Make the Sherman County lane's current identity conflict
> unmistakable, prevent a Stevens County plan from being used as Sherman
> evidence, and define the smallest safe correction path without silently
> creating, moving, deleting, releasing, or publishing anything.

> **This directory does not currently contain a Sherman County build plan.**
> It contains this README and a file named
> `stevens_county_focus_mode_build_plan.md`. That file identifies itself
> throughout as a **Stevens County** plan and is byte-identical to the plan

> [!CAUTION]
> **The foreign plan is conflict evidence, not a substitute county artifact.**
> Do not relabel its Hugoton natural-gas, Stevens County, property/mineral,

1. pin both county directory trees and the duplicate blob;

4. preserve the correct Stevens copy;

## 11. Smallest safe follow-up

Before a structural correction or a new Sherman plan, build one deterministic,
no-network **county-identity fixture packet**.

### Proposed fixture matrix

| Fixture | Expected result |
|---|---|
| Path scope `sherman`; artifact metadata county `stevens` | `ERROR` — path/metadata mismatch |
| Same build-plan digest registered for Sherman and Stevens | `HOLD` or fail-closed `ERROR` |
| Sherman directory contains no authentic Sherman plan | `ABSTAIN` |
| Correct Stevens path and Stevens metadata agree | `ANSWER` for identity-only validation |
| Request tries to relabel foreign plan as Sherman | `DENY` |
| Correction removes Sherman duplicate while preserving Stevens copy and references | `PASS` in a dedicated migration test |
| Public request asks a Sherman county claim with no EvidenceBundle | `ABSTAIN` |
| Release candidate includes the foreign plan under Sherman | `DENY` |

### Acceptance boundary

The packet should prove identity matching, duplicate detection, reference-safe
correction, and fail-closed behavior. It must not introduce production data,
network calls, external county facts, or public release state.

A later, separate Sherman planning slice should begin only after the identity
correction is resolved or explicitly bounded and should derive its thesis,
sources, risks, and tests from Sherman-specific evidence.

## 14. Maintenance, correction, and rollback

### Before merge

Rollback is to close or abandon the draft pull request and its branch. The
default branch retains the one-byte README and the existing duplicate-tree
state. Remote branch deletion requires separate authority.

### After merge

A transparent revert or forward-fix pull request should restore or correct the
README and generated receipt together. Shared history must not be rewritten.

### Structural correction

The foreign plan's rename, movement, tombstone, or deletion is outside this
slice. That work requires:

- a pinned base and exact duplicate identity;
- inbound-reference and consumer inventory;
