### Product thesis

**PROPOSED:** A public-safe Kiowa County Focus Mode could connect official, dated evidence about the Greensburg tornado and civic recovery with bounded sustainable-rebuilding examples, Big Well and meteorite context, historic geology/groundwater context, county-scale agriculture, safe official-current routing, and visible cultural-authority limits.

The durable product value is not a dramatic map. It is a trust-visible learning surface that can show why some content is supported, why some is stale or historically bounded, and why some is withheld.

### Intended first-slice promises

| Proposed capability | Bounded meaning |
|---|---|
| County and Greensburg orientation | General public-safe orientation with verified geometry and attribution |
| Historic tornado event card | Dated event context with a persistent “not a current warning” notice |
| Recovery timeline | Generalized public-memory chronology without household or parcel detail |

## Source roles and temporal fitness

The build plan records a dated source seed ledger. This README preserves its role separation without rechecking or re-admitting those sources.

| Plan-recorded source role | May support after admission | Must not silently become |
|---|---|---|
| NWS historic hazard authority | Dated event history and generalized public context | Active warning, forecast, shelter, evacuation, or current risk |
| City public memory and civic recovery | Locally stated history, public attraction context, and bounded rebuilding narrative | Individual damage truth, engineering safety, present performance, or Kiowa cultural authority |
| Federal building/energy case study | A specific documented rebuilding example | Whole-city resilience score or current infrastructure condition |
| Historic KGS science | Dated geology/groundwater and meteorite-related context | Current water safety, supply, well, health, or legal conclusion |
| KDA/NASS statistical aggregate | County values for a stated reporting year | Producer, parcel, property, damage, or water-use inference |
| County emergency public routing | Public contact or authority routing | Emergency status, operations plan, responder location, or tactical content |
| Kiowa Tribe official authority | Sovereignty and cultural-authority boundary; potential future review path | Automatic authorization for a KFM cultural layer or generated narrative |
| Restricted or official-use operational material | An internal exclusion/quarantine record with minimal safe metadata | Public layer, excerpt, summary, model context, or searchable tactical content |
| Generated explanation | Interpretation of released evidence within allowed scope | Evidence, warning authority, policy decision, cultural authority, or release proof |

### Required time fields

Any future claim-bearing Kiowa object should keep these times distinct where relevant:

- event time;
- observation or source-record time;
- publication/update time;
- retrieval time;
- statistical reference year;
- validation time;
- release time;
- correction or withdrawal time.

A historic source can remain valuable while being unfit for a present-tense question. The public UI should make that distinction visible rather than relying on users to infer it.

### Freshness behavior

| Request type | Minimum time behavior |
|---|---|
| “What happened in Greensburg in 2007?” | May `ANSWER` only from released, citation-valid historical evidence |
| “What is the weather danger now?” | `ABSTAIN`; route to qualified official current sources |
| “Is the city currently resilient or safe?” | `ABSTAIN` unless a narrowly scoped, current, released assessment exists |
| “Is my well or water safe now?” | `ABSTAIN`; historical KGS context is insufficient |
| “What were county agricultural totals in 2022?” | May `ANSWER` only with year, source role, limitations, and released aggregate evidence visible |

<a id="public-safety-rights-and-sensitivity"></a>

## Public safety, rights, and sensitivity

### Fail-closed boundary

| Sensitive or consequential request | Default outcome | Required posture |
|---|---|---|
| Current warning, shelter, evacuation, road, or emergency action | `ABSTAIN` | Direct users to qualified official-current channels; do not restate stale or cached status |
| Tactical emergency plan, responder staging, shelter security, or restricted operational detail | `DENY` | Exclude from public and model context; retain only minimal governed exclusion metadata |
| Critical-facility, utility dependency, or infrastructure vulnerability | `DENY` | Generalize or withhold; never confirm sensitive detail through denial text |
| Named-person, household, address, parcel, trauma, injury, death, or damage detail | `DENY` | Keep public history at generalized community scope |
| Present resilience, facility safety, or utility reliability inferred from rebuilding examples | `ABSTAIN` | Require current, scoped, released evidence |
| Present groundwater, well, water-quality, health, or legal conclusion from historic science | `ABSTAIN` or `DENY` | Require qualified current authority and policy |
| Private meteorite, crater, collecting, or access location | `DENY` | Public attraction/general science context only |
| Kiowa cultural narrative without appropriate Tribe-authoritative evidence and review | `ABSTAIN` or `DENY` | Defer substantive representation |
| Agriculture joined to private operation, parcel, disaster damage, or water use | `DENY` | Preserve aggregate-only use |
| Unreleased or lifecycle-internal source, layer, candidate, or model output | `DENY` or `ERROR` | Public clients remain behind governed interfaces |

### Rights and geometry

A public webpage, PDF, map, or official source can still have unresolved reuse rights, attribution duties, precision risks, or source-role limitations. Before public use, a future implementation must record:

- authoritative source identity;
- allowed use and redistribution posture;
- required attribution;
- geometry authority and permitted precision;
- sensitivity and harmful-precision classification;
- source date and freshness;
- evidence and citation scope;
- review state;
- release eligibility;
- correction and rollback dependencies.

Discoverability is not admissibility. Official hosting is not automatic public derivative-display permission. A polished card is not release evidence.

### Cultural authority

The build plan correctly treats the county-name and cultural question as a separate authority boundary. This README does not assert Kiowa history or speak for the Kiowa Tribe. It records only the future requirement: substantive Kiowa cultural representation needs appropriate Tribe-authoritative evidence, permitted scope, and review.

## Finite outcomes and reason codes

The only public runtime terminal outcomes used here are:

| Outcome | Meaning |
|---|---|
| `ANSWER` | Released evidence resolves, policy permits, citations validate, and requested space/time/precision are in scope |
| `ABSTAIN` | Evidence, currentness, authority, rights, geometry, review, or scope is insufficient |
| `DENY` | Policy blocks the request because exposure or use is unsafe or prohibited |
| `ERROR` | Contract, schema, resolver, evaluator, adapter, or governed-interface execution failed |

`EXCLUDE` in the build plan is an **internal source-admission or release disposition**, not a fifth public runtime outcome.

### Proposed Kiowa reason-code vocabulary

The following codes are planning candidates from the linked build plan. Their presence in Markdown does not prove a contract, schema, evaluator, fixture, or API implements them.

| Proposed code | Intended use | Outcome |

### Maintenance triggers

Re-review this README when any of the following changes:

- the Kiowa build plan is edited, renamed, moved, superseded, or retired;
- the county index is recomputed;
- ADR-0027 changes status;
- the current Focus docs path changes;

- a hazard/currentness, emergency, infrastructure, cultural, property, water, or scientific-resource review changes;
- a Kiowa release, correction, withdrawal, rollback, deployment, or public endpoint is created.

### Structural migration

Any future move from the singular snake_case lane must:

1. verify the accepted target and owning root;
2. inventory all inbound links, automation, generated receipts, branches, and external consumers;
3. preserve one writable authority;
4. use history-preserving movement where available;
5. update authorized references atomically or through a documented read-only compatibility surface;
6. retain correction and rollback records;
7. avoid creating both singular and plural writable county trees.

### Documentation rollback

Before merge, rollback means closing or abandoning the draft pull request and branch; branch deletion is a separate administrative action. After merge, use a transparent revert or forward-fix pull request against the actual merged commit. Do not rewrite shared history.

### Public correction boundary

This README creates no public Kiowa artifact, so a Git revert is sufficient for its own repository effect. A future released map, payload, cached card, search index, export, or AI answer would require correction propagation, withdrawal/supersession state, cache invalidation where applicable, and a usable rollback target beyond source-control reversal.
