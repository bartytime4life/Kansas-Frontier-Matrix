# Kansas State-Scale Focus Composition Planning Index

> **Purpose.** Record the one proposed Kansas-wide Focus composition identity,
> show what is actually present in the repository, and prevent a planning row
> from being mistaken for scope registration, a geographic lane, validation,
> evidence closure, release, deployment, or publication.

> [!IMPORTANT]
> **There is one proposed identity and zero verified geographic state lanes.**
> ADR-0028 proposes `scope_kind: state` and `scope_id: kansas-state`, but remains
> `proposed`. No direct `docs/focus-mode/state/kansas-state/` lane exists at the
> pinned repository snapshot.

> [!WARNING]
> **This index is not parsed by the current Focus index validator.**
> `tools/validators/validate_focus_mode_index.py` parses a county table, permits
> `county`, `region`, and `corridor`, expects a plural Focus tree, and contains no
> `state` scope. It is also absent from the validator orchestrator registry.
> The prior claim that this file was validator-parseable is unsupported.

> [!CAUTION]
> **The current `state/` tree is mixed authority.** `STATE_INDEX.md` and the state
> template are geographic composition planning; the sibling README and state
> documents describe runtime, lifecycle, review, payload, revocation, and
> rollback state. Accepted Directory Rules v2 makes the required future result
> `SPLIT`, while exact target paths remain `HOLD`.

> [!NOTE]
> **An index row is inventory, not lifecycle.** A table row, owner placeholder,
> priority, source seed, schema-valid object, passing check, commit, pull request,
> or merge cannot create a source admission, EvidenceBundle, PolicyDecision,
> ReviewRecord, release, correction, rollback, deployment, or publication.

## 1. Status and inventory terms

The prior file reproduced a lifecycle-like status enum. This edition uses
human-readable inventory labels because no accepted state-scope machine contract
or state-aware validator currently owns those values.

| Label | Meaning in this index | Governing effect |
|---|---|---|
| `PROPOSED_IDENTITY` | A proposed ADR names a scope kind or ID, but the decision is not accepted and the identity is not registered. | Preserve as design lineage; do not create a lane or public claim. |
| `NO_GEOGRAPHIC_LANE` | No direct geographic state-composition directory exists under the checked state tree. | Prevent duplicate assumptions; implementation remains absent. |
| `UNREGISTERED` | No accepted machine registration was verified for the proposed state scope. | Scope cannot be treated as active. |
| `VALIDATOR_UNSUPPORTED` | The current validator does not parse this index or admit `state`. | No validator outcome may be claimed for the row. |
| `NOT_RUN` | A named executable check was not run in this documentation slice. | Do not infer a pass or fail. |
| `NOT_ESTABLISHED` | The object, authority, or flow was not verified as implemented. | Remains fail closed. |
| `NEEDS VERIFICATION` | A concrete repository, policy, evidence, reviewer, or runtime check remains. | Narrow the claim until checked. |
| `HOLD` | Acceptance, ownership, placement, sensitivity, evidence, review, or release prerequisites are unresolved. | Do not create a new home or advance public state. |
| `DENY` | A proposed action would create parallel authority, expose protected state, or bypass governance. | Reject that action. |

### Truth labels

| Label | Meaning |
|---|---|
| `CONFIRMED` | Verified from current-session repository bytes or remote state. |
| `PROPOSED` | A design or decision not accepted or implemented. |
| `CONFLICTED` | Current sources or writable surfaces make incompatible claims. |
| `LINEAGE` | Retained prior design or planning context; not current authority. |
| `UNKNOWN` | Evidence does not establish the material claim. |
| `NEEDS VERIFICATION` | A concrete check can resolve the question but has not been completed. |

> [!NOTE]
> Geographic state scope, runtime outcome, lifecycle stage, review state, payload
> state, validator result, and revocation state are separate axes. This index

## 4. Identity, cardinality, and path boundary

### Proposed identity

ADR-0028 proposes:

| Field | Proposed value | Current authority |
|---|---|---|
| Display label | `Kansas` | `PROPOSED` |
| `scope_kind` | `state` | `PROPOSED / UNREGISTERED` |
| `scope_id` | `kansas-state` | `PROPOSED / UNREGISTERED` |
| Current cardinality | exactly one | `PROPOSED` |
| Geometry identity | separate versioned reference | `NOT_ESTABLISHED` |
| Time profile | separate versioned reference | `NOT_ESTABLISHED` |
| Domain profile | separate reference and digest | `NOT_ESTABLISHED` |
| Exact documentation path | no value selected by identity | `HOLD` |

Historical periods, themes, stories, releases, and UI presets would be versions
or views of the one proposed identity, not additional state-scope IDs.

### Why the row remains single

The current project scope is Kansas. Multi-state, interstate, frontier-region,
or national compositions would be different scope decisions; they must not be
added as alternate spellings of `kansas-state`. A future second state-scale row
would require:

1. an accepted decision defining the new scope and cardinality;
2. stable machine identity;
3. a non-conflicting placement decision;
4. a versioned domain profile;
5. fixtures and validator coverage;
6. evidence, policy, review, release, correction, and rollback closure.

### Identity does not select a path

`kansas-state` is an identity proposal, not a directory instruction. It does not
by itself authorize:

- `docs/focus-mode/state/kansas-state/`;
- `docs/focus-modes/kansas-state/`;
- a new repository root;
- a copied statewide domain corpus;
- a public API route or map layer.

| Outcome | Bounded meaning |

- a policy denial must not be converted into an evidence abstention or an error.

## 13. Maintenance, correction, and rollback

### Update this index when

- ADR-0028 changes effective status or is superseded;
- a state scope registry is created or changed;
- the domain profile gains accepted identity and digest;
- the mixed state tree receives path decisions;
- a geographic state lane is created, moved, mirrored, or retired;
- the state template is corrected or superseded;
- a state-aware validator, fixtures, tests, or registry entry is added;
- a state payload contract/schema/validator closes;
- source, evidence, policy, review, release, correction, rollback, deployment, or
  public parity becomes verifiable;
- a consumer or inbound-link inventory changes migration risk.

### Correction procedure

A documentation correction should:

1. pin the affected index version, blob, and repository commit;
2. identify the inaccurate row, count, path, or authority claim;
3. cite the newer decision, registry, contract, schema, test, run, or artifact;
4. preserve compatibility anchors where feasible;
5. update dependent docs or record why they remain separate;
6. avoid creating machine, policy, lifecycle, or release authority through prose;
7. define rollback to a known prior blob or a bounded forward correction.

### Rollback

Before merge, close or abandon the draft pull request and branch. Branch deletion
is separate.

After merge, transparently revert the update commit or restore prior blob
`8d0b631bd53e6af3747417ee813c791fc67a9c3c`. Do not rewrite shared history.

A Git revert can restore this index's bytes. It cannot unregister a scope, retract
a released payload, invalidate public caches, issue a correction notice, or
execute public rollback.
