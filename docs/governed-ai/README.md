## 7. Governed request flow and finite outcomes

The intended order is evidence- and policy-first:

```text
bounded caller request
  -> authenticate and authorize
  -> resolve released evidence, freshness, and correction state
  -> policy precheck and context minimization
  -> provider-neutral adapter
  -> structured candidate validation
  -> citation validation
  -> policy postcheck and precision enforcement
  -> RuntimeResponseEnvelope
  -> separate AIReceipt accountability
  -> governed client projection
```

A model response is an untrusted candidate inside this sequence. It is never the root truth object.

| Outcome | Minimum interpretation |
|---|---|
| `ANSWER` | Sufficient governed evidence, allowed policy state, valid structured output, validated citations, and safe postcheck support a bounded answer. |
| `ABSTAIN` | Evidence, freshness, citation, scope, or continuity is insufficient. |
| `DENY` | Policy, rights, sensitivity, authorization, release state, or precision rules prohibit the request or response. |
| `ERROR` | Safe completion is impossible because input, dependency, adapter, validation, or system state failed. |

> [!WARNING]
> Finite outcome vocabulary does not itself authorize an answer. A schema-valid `ANSWER` is still only a shaped object until evidence, policy, citation, review, and release obligations are satisfied.

## 8. Security, rights, sensitivity, and privacy

Every governed-AI implementation must preserve these fail-closed boundaries:

- public browsers and ordinary clients never call a model provider directly;
- source text, retrieved documents, tool output, and model output are untrusted data, not instructions or authority;
- prompt injection is handled before model output reaches a governed envelope;
- credentials, private endpoints, raw prompts, protected context, hidden reasoning, and chain-of-thought are not committed or exposed as evidence;
- adapters receive minimized, policy-allowed context rather than unrestricted stores or full canonical objects;
- living-person, genomic, archaeological, rare-species, cultural, land/title, infrastructure, and harmful-precision material is denied, generalized, redacted, staged, or held when support is unclear;
- logging, telemetry, errors, caches, receipts, and diagnostics must not become side channels for protected inputs or model output;
- local execution does not waive evidence, rights, sensitivity, citation, review, or release requirements.

The detailed threat posture lives in [`PROMPT_INJECTION.md`](../architecture/governed-ai/PROMPT_INJECTION.md) and [`BOUNDARIES.md`](../architecture/governed-ai/BOUNDARIES.md).
